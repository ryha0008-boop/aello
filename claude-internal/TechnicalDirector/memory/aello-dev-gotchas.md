Two non-obvious things when developing/testing aello on Windows:

1. **`cargo install --path . --force` fails with "Access is denied" when any `aello.exe` is running** (live TUI/run sessions hold the binary). Fix: rename the running exe out of the way first — `Rename-Item ~/.cargo/bin/aello.exe aello.exe.old-<tag> -Force` — then `cargo install`. Windows allows *renaming* a running exe (just not overwriting/deleting). aello's startup sweep cleans `aello.exe.old*` later. Alternatively use `aello update` (it does the rename trick internally, pulling the released binary).

2. **Claude Code print mode (`claude -p`, i.e. `aello run <bp> -p "..."`) does NOT inject persistent project memory** (`<env>/projects/<slug>/memory/MEMORY.md`). Only interactive sessions load it. Verified by control test: even an env with memory definitely loaded (TechnicalDirector) reports "NO MEMORY LOADED" under `-p`. So you can't use `-p` to verify a memory-seeding feature — verify by path-identity instead (the seeded `projects/<slug>/memory/` dir must match the slug Claude writes its session `.jsonl` into; `sessions::encode_project_path` produces it). See [[aello-ci-release]].

3. **`gh issue view <n>` fails on this machine** with `authentication token is missing required scopes [read:project]` (and sometimes API timeouts) — the default view tries to fetch linked project data. Read issues with `gh issue view <n> --json title,body -q '.title + "\n\n" + .body'`, and `gh issue list` for the list. Commits with `Closes #n` trailers still auto-close the issues on push regardless.

4. **A new universal skill (`/handoff`, `/twosentences`, `/note`, …) does NOT backfill to already-placed envs.** `place()` re-seeds the universal skills on every run, but only for the env being placed, and only via the *installed* binary — so existing env dirs across the machine stay stale until you `aello run` each one again with a freshly `cargo install`ed binary. The user runs ~29 envs across ~20 repos and does NOT want to re-run them. When you add a universal skill, **seed it directly** into every existing env: `find /c/Users/H -maxdepth 6 -name .aello.toml`, derive the blueprint name from the `.claude-env-<name>` dir, and write `<envdir>/skills/<skill>/SKILL.md` with the name substituted (the per-blueprint name is woven into the skill body). Design note for `/note`: it **overwrites** `<target>.NOTE.md` (single current note), not appends — the user reads a note the moment it's left, so accumulation is unwanted.

5. **`aello update` cannot deliver work that lives on a branch — and it fails silently.** It fetches the latest *release*, and CI only builds on pushes to `main`. Testing a branch feature means `cargo install --path . --force` (see #1), not `update`. The trap is that the released version can be *higher* than the branch build (2026-08-01: installed 0.1.52 from a release vs 0.1.51 on `launch-prep`), so `aello update` looks like it upgrades while actually removing the feature you wanted to test. Check `aello <cmd> --help` for the new flag, not the version number. After `cargo install`, the local build's lower version is cosmetic — CI renumbers on merge.

6. **Print mode fires hooks even though it skips memory.** Complementing #2: `aello run <bp> -p "..."` does load the persona and does run `Stop`/`SessionEnd` hooks, so it's a valid way to place an env and exercise hook behaviour headlessly. Only persistent *memory* injection is missing.

7. **Claude Code's cwd→projects-dir encoding folds EVERY non-alphanumeric char to `-`, not just separators.** Verified empirically 2026-07-08: a real folder `…\work\human_behavior` is stored by Claude under `~/.claude/projects/` as `…-work-human-behavior` (underscore → hyphen; case preserved). So the rule is `replace([^A-Za-z0-9], '-')` — spaces and `_` fold too, not only `\ / : .`. aello's `sessions::encode_project_path` previously only folded `\ / : .`, so for any project path containing `_`/space it pointed seeded memory + `--resume` at a dir Claude never reads (silent no-op). Fixed on branch `audit-fixes-2026-07-08`. This is the ground truth behind the path-identity requirement in gotcha #2. See [[aello-architecture-decisions]].

8. **aello's own config is at `%APPDATA%\aello\config\config.toml`** — note the extra `config/` level that `directories::ProjectDirs` adds on Windows. It is not in `~/.config/aello/`, not in `%APPDATA%\aello\`, and a `find` over the obvious places misses it entirely; this cost several commands on 2026-08-02. That file is the only place capabilities are recorded, so it is what you check when you need to know what a blueprint actually has.

9. **A `SessionStart` hook can inject text into the new session, and it works** — verified end to end on 2026-08-02, not assumed from docs. Print `{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": "..."}}` to stdout and Claude reads it as context. Confirmed by planting a note containing a nonsense codeword, running `aello run <bp> -p "what is the codeword?"`, and getting the codeword back. This is what makes `/handoff` and `/note` actually self-consuming (see [[aello-voice-capability]] for the hook-file layout). Worth remembering because the contract is external to this repo and easy to get subtly wrong — plain stdout is also accepted for SessionStart, but the JSON form is explicit.

10. **After hand-backfilling env dirs, `cargo install` immediately — an older binary silently undoes the work.** `place()` rewrites the bundled files (hook scripts, universal skills) into `<env>/hooks/` on **every** run, unconditionally, so a stale `~/.cargo/bin/aello` overwrites a fresh backfill with the version it was built from, on the next `aello run` of that env, one env at a time. Complements #4: #4 is why a backfill is needed at all, this is why it doesn't stay done. The tell is nasty — most envs stay correct while whichever ones you happen to run go quietly stale. The reusable script pattern (glob `Desktop/*/**/.claude-env-*` filtered to dirs holding `.aello.toml`, byte-compare each bundled file, `--apply` to copy, then a `--verify` pass that actually *runs* the copy and checks what it reports) is carried forward per bump — latest copy `…\058e76d8-…\scratchpad\backfill_hookv5.py`, see [[aello-voice-capability]] #11; 39 envs on 2026-08-02, up from 38 the day before.

11. **This machine can screenshot a web page without downloading a browser.** Playwright *browsers* already sit at `%LOCALAPPDATA%\ms-playwright` (several chromium revisions), but the `playwright` npm package isn't installed in any project — and a fresh `npm i playwright` then fails at launch with "Executable doesn't exist at …chromium_headless_shell-<newer rev>", because the new package expects a revision that isn't there. Don't run `npx playwright install` (~150 MB); install the package into the scratchpad and pass `executablePath` to a revision that does exist, e.g. `chromium.launch({ executablePath: 'C:\\Users\\H\\AppData\\Local\\ms-playwright\\chromium-1228\\chrome-win64\\chrome.exe' })`. Second trap: `fullPage` screenshots of a page using IntersectionObserver scroll-reveals come out with **blank mid-page sections** — jumping straight to the bottom and back never intersects the middle. Step the scroll down in half-viewport increments first, then capture.

12. **Resuming through aello is a full `aello run` — `place()` runs first.** `run_blueprint` calls `project::place()` unconditionally (`main.rs:551`) *before* it even interprets `--resume` (line 567); resume only changes an argument passed to `claude`. So `aello run <bp> --resume` (and the TUI) re-seeds skills, rewrites the bundled hook scripts, and self-heals `settings.json` exactly like a cold start — which makes "exit every session and relaunch" a valid way to roll a template or hook change across the fleet. It does **not** hold for resuming from *inside* a running Claude session, or for `claude --resume` run directly: neither touches aello, so neither picks anything up. Complements #10 — this is the mechanism by which a stale installed binary reaches an env.

13. **Backfilling a *hook* is two parts; backfilling a script is one.** The voice backfills (#10) are pure file copies, so the reusable script pattern covers them. A hook is different: `hooks/<x>.py` must be written **and** registered as an entry in that env's `settings.json`, because `settings.json` is written once at first placement and never clobbered — `ensure_own_hook` self-heals it, but only when that env is next placed. On 2026-08-02 the SessionStart hook was in 2 of 39 envs for this reason. Key on aello's **script name**, not the event key (a third-party hook on the same event must not block the heal), and check both halves independently: the audit that day found 6 envs registering `session-end.py` with no such file on disk (a hook that fires and fails) and 2 envs with no `Stop`/`speak.py` entry at all (silent, against the "every env speaks" invariant). Script: `…\39e11acf-…\scratchpad\backfill_hookregs.py` — covers all four owned hooks, writes missing scripts, refreshes stale ones, and verifies both halves.

15. **No persona should carry a TL;DR section — and a *generated* one must not reintroduce it.** The experiment recorded here on 2026-08-03 (the instruction moved out of the global persona onto a hand-registered `UserPromptSubmit` hook in TechnicalDirector only) **ended the same day and shipped**: `c34faf9` bundles `src/hooks_user_prompt_submit.py`, `place()` registers it, and all 41 envs were backfilled — so the TL;DR rule now arrives on every prompt, everywhere, along with conciseness and anti-sycophancy. `injects_tldr_per_turn` makes `ensure_tldr_instruction` skip the persona append whenever that hook is registered, so a cleared persona stays cleared. Consequences: the ~40 envs placed earlier keep a duplicate copy in their personas (harmless, and not worth editing a user-owned file to remove), and `/regenerate-claude-md` is instructed not to write the section — nor to restate the other two rules, which would cost context on every turn for nothing. Enforcement never lived in the instruction anyway: `speak.py` exits 2 on a response with no `TL;DR:` line and asks for one, so the worst case was ever an extra round trip. See [[aello-voice-capability]].

18. **`Cargo.lock` re-dirties itself within seconds — a background rust-analyzer rewrites it, not your build.** Long assumed to be "every `cargo build` dirties it" ([[aello-ci-release]]), which is only half true: on 2026-08-03 `git checkout -- Cargo.lock` was measured reverting the `aello` version line to the committed 0.1.51 and finding it back at the manifest's version **2 seconds later with no cargo command run**. Something is watching the manifest. The practical consequence is that `git restore Cargo.lock && git pull --rebase` **cannot** work — the file is dirty again before the rebase starts, and the rebase aborts with "cannot rebase: You have unstaged changes". Use **`git pull --rebase --autostash`**, which stashes and restores atomically. Also: a `git stash` taken while this is happening contains `Cargo.lock`, so a later `git stash pop` silently re-dirties the tree — and a `pop` that fails on a dirty tree keeps the stash, so check `git stash list` before assuming edits were lost (they were not; that is how the v0.2.0 release.yml edit survived).

19. **The docs site is generated from `docs/`, so a doc edit redeploys the website.** Shipped 2026-08-03: `site/lib/docs.ts` reads `../docs/*.md` at build time and `site/app/docs/` renders them, so `docs/` now has **three** readers — the binary (`docs.rs`), the TUI (`?`) and the web — from one source. `.github/workflows/pages.yml` triggers on `site/**` **and `docs/**`** for exactly this reason. Two things to know: the site build needs `NEXT_PUBLIC_BASE_PATH=/aello` for the GitHub Pages *project* path (read by both `next.config.ts` and `lib/docs.ts`, unset locally so `npm run dev` stays at the root); and the landing page's Workflows section resolves its anchors from `docs/workflows.md`'s rendered headings and **throws at build time** if a heading is renamed, rather than shipping a dead `#anchor`. `actions/configure-pages` needs `enablement: true` or the first run fails with "Get Pages site failed" — the default is to fail rather than switch Pages on.

20. **`.gitignore` does nothing to a file git is already tracking — adding the rule is only half the fix.** On 2026-08-03 `AUDIT-2026-07-08.md` was found still on GitHub, ~6 weeks after commit `dec3fd9` added `AUDIT-*.md` to `.gitignore` specifically to honour the audits-never-go-to-GitHub ruling. 21. **Python's `glob` never matches a leading dot with `*` — so a fleet scan over `.claude-env-*` silently returns nothing.** Cost a false "0 placed envs found" on 2026-08-03, which read exactly like a correct answer. `os.path.join(root, "*", ".aello.toml")` finds nothing, because the env dir component `.claude-env-X` starts with a period and `*` skips dotted names; spelling the dot literally (`".claude-env-*"`) fixes it and found 41. Bash `find` has no such rule, which is why the same sweep works there and is the safer default. 22. **An aello older than 0.2.8 breaks on a migrated config.** `claude_md` now holds `none` or `custom` for most blueprints, and a pre-0.2.8 `templates::resolve` treats an unknown name as a *file path* — so it fails with "not a built-in template or a readable file" and the launch aborts. Deliberate (a persona that silently vanished was the worse bug), but it makes an old binary a hard stop rather than a degradation. Same class as gotcha #4's pre-0.2 hazard: the config migrates forward on every load and nothing migrates back. The migration only *persists* when aello next saves — **and on this machine it has now saved** (2026-08-03, the first `aello persona` run): eight blueprints went from an absent key or `sysadmin` to `none`/`custom` in `config.toml` on disk, in the same write. So the hazard is no longer hypothetical here; any aello older than 0.2.8 is now a hard stop on this config, not a degradation. Back the file up before any command that writes it — a restore is how an earlier real-config test got undone.

24. **Mining contextdb: the user's own words are in two places, and printing them on Windows crashes.** A record is `<contextdb>/<project>/<blueprint>/<ts>_<session>_end.jsonl`, one JSON object with keys `agent`, `handoff`, `kind`, `session`, `timestamp`, `transcript`, `trigger` — the `handoff` field holds the whole `/handoff` note, which is the durable summary. 30. **Git Bash silently rewrites a leading-slash argument into a Windows path, and it can turn a failing test into a passing one.** Measured 2026-08-06. `aello run x -p "/twosentences"` reached the child process as `C:/Program Files/Git/twosentences` — MSYS argument conversion. The damage was not the failure but the **success**: the rewritten string contains a space, which happened to satisfy the CLI's "no one-word prompts" rule, and the model then *guessed* the right skill from the path, so the run looked like a clean end-to-end verification and was reported to the user as one. 27. **A bundled hook script's docstring is executed code on every prompt — a stray `\s` in it warns on stderr in all 41 envs.** Written 2026-08-04. The `UserPromptSubmit` docstring quoted `extract_tldr`'s regex, and Python 3.14 emits `SyntaxWarning: invalid escape sequence` for `\s` in a non-raw string. Nothing failed, nothing was reported, and the JSON on stdout was perfectly valid — the noise only surfaced because a verification run happened to capture stderr. Fixed in `39f9eaf`. Same family as [[aello-voice-capability]] #9: a hook that keeps working while quietly doing something wrong.

28. **A newly-set Windows User environment variable never reaches a running process — so a fleet switch can be "on" everywhere and doing nothing.** Hit on 2026-08-06 verifying `HOOK_VERSION` 13's Telegram delivery. `REVOICED_TELEGRAM`, `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` were correctly persisted at User scope, and `[Environment]::GetEnvironmentVariable(name,'User')` returned all three — but `$env:NAME` in this session was empty, because Windows only seeds a process environment at creation. Every Claude Code session started before the variables were set therefore runs a `speak.py` that sees the feature as off, sends nothing, and says nothing. Verifying from such a shell reports a false negative that looks exactly like a broken rollout; verifying from a *fresh* shell reports a true positive that is false for every running env. Read the persisted value and inject it (`Set-Item "Env:\$v" ([Environment]::GetEnvironmentVariable($v,'User'))`) to test the code, then say separately that running sessions need a relaunch — those are two different claims and conflating them is how "it works" gets reported for a fleet where it does not. See [[aello-voice-capability]] #17.

31. **crossterm's `enable_raw_mode()` succeeds with a piped stdin on Windows, so "try raw mode, fall back if it fails" hangs instead of falling back.** Measured 2026-08-06 writing the hidden API-key prompt for `aello login --agent cline`. crossterm opens `CONIN$` directly rather than using the process's stdin handle, so raw mode is entered happily under `printf … | aello login`, and the subsequent `read()` waits on the *console* while the pipe sits unread — the command hung until a `timeout` killed it, with no error and no output after the prompt. Gate an interactive read on **`std::io::IsTerminal::is_terminal(&std::io::stdin())`**, never on whether raw mode can be entered. Test both paths: the piped one is the one that breaks, and it breaks silently. Every exit path (Ctrl+C, Esc, read error) must `disable_raw_mode()` — a terminal left raw is worse than the credential the change was hiding.

32. **Three encoding traps, each of which made a test or a claim agree with the bug.** All 2026-08-06.
    - **A UTF-16 file without a BOM is byte-for-byte valid UTF-8**, so a test that writes one measures nothing — UTF-16LE ASCII interleaves NUL bytes, and UTF-8 accepts every one of them. `read_to_string` *succeeded*, the guard never fired, and the test asserting an error failed. The BOM (`FF FE`) is the part no UTF-8 string can contain, and it is what Notepad actually writes.
    - **`json.load(sys.stdin)` does not raise on a byte the console code page cannot map — `sys.stdin.errors` is `surrogateescape`.** The undefined byte becomes a lone surrogate (U+DC81) and decoding continues, so `E4 B8 81` came back as three mojibake characters with the JSON structure and every ASCII field intact. Both the audit and aello asserted a `UnicodeDecodeError` and built an argument on it ("the plan-mode hook fails open"); wrong, because `tool_name` is ASCII and decodes cleanly either way. The real damage is in paths: round-tripping a real `丁file.jsonl` path through cp1252 makes `open()` fail with `FileNotFoundError`, which is how the SessionEnd transcript archive silently degrades back to a pointer. CodeAuditor caught it by probing the claim instead of re-reading the code — and that is why its `/audit` skill now requires an executable probe before a finding may be marked CONFIRMED.
    - **`subprocess.run(..., text=True)` decodes with the *locale* encoding**, so piping `git show HEAD:file` through it and writing the result back as UTF-8 double-encodes every em dash into `â€”` across the whole file. Caught only because the staged diff was 176 lines instead of 14. Capture bytes and `.decode('utf-8')` explicitly.

33. **`open(path, 'w')` truncates before it writes, so a `UnicodeEncodeError` mid-write leaves the file empty — and a memory file is the worst place to learn that.** Hit during a `/sync` on 2026-08-06. A patch script carried a literal lone surrogate in its replacement text — a doubled backslash-u escape collapsed to a single one somewhere between the tool call and Python — the write raised "surrogates not allowed", and `aello-dev-gotchas.md` went from 27,879 bytes to **0**; nothing after it in the script ran. Recovered in full from `claude-internal/TechnicalDirector/memory/`, the first time the tracked mirror has been needed as a backup, which is the argument for `restore_from_mirror` restated from the other direction. Three rules: patch anything you cannot regenerate through a temp file plus `os.replace`; keep backslash escapes out of shell heredocs entirely (the Write/Edit tools do not mangle them, `bash -c` with a heredoc does — the *same* script failed twice, once truncating a file and once only at parse time); and check the byte count of what you just edited before moving on.

34. **A multi-line PowerShell command in this tool wrote a `.lnk` with every property blank, and `Save()` returned success.** 2026-08-07. Creating a desktop shortcut via `WScript.Shell` — `$s.TargetPath = …`, `$s.Arguments = …`, `$s.IconLocation = …`, `$s.Save()` across separate lines — produced a 2,073-byte file whose `TargetPath`, `Arguments` and `Description` all read back as empty strings on reopen, and `Start-Process` on it failed with "The system cannot find the file specified". Rewriting the identical calls as **one semicolon-joined statement** worked first time. The tool's own docs say not to separate commands with newlines; this is what ignoring that looks like — not an error, a silently empty artifact. **Always read a `.lnk` back** with a fresh `CreateShortcut` and assert the properties, because a blank shortcut is the same size and shape as a good one. Related trap in the same session: the user renamed the shortcut mid-session (`aello site.lnk` → `Aello.lnk`), so a later `Start-Process` by the old name failed for a completely different reason and looked like the same bug.

35. **Ports 3000–3002 on this machine are already taken, and Next silently increments past an occupied port.** Projectifiable holds 3000, ScenarioAnalysis Dashboard holds 3001. 36. **The whole site's motion was off because Windows animations were off, and nothing on the page said so.** 2026-08-07. `HKCU\Control Panel\Desktop\WindowMetrics\MinAnimate = 0` → Chromium reports `prefers-reduced-motion: reduce` → `globals.css` honours it by disabling the scroll reveal and clamping every transition to 0.01ms. The user reported "no motion apart from hover states"; the site was fine, the machine was suppressing it. **Probe the browser, don't infer from the registry**: write a two-line HTML that renders `matchMedia('(prefers-reduced-motion: reduce)').matches` and screenshot it with headless Edge — headless *does* inherit the OS setting here (`reduce=true` before, `false` after). Turning it on takes **two** SPIs, because the Windows Settings toggle drives both and writing one leaves the pair inconsistent enough to revert: `SPI_SETCLIENTAREAANIMATION` (0x1043, the one Chromium reads) **and** `SPI_SETANIMATION` (0x0049, `MinAnimate`). Note `SystemParametersInfo` takes four arguments — calling the GET with three raises a PowerShell overload error while the surrounding script prints a stale `0` and reads like a measurement.

37. **An expo-out easing makes a duration token lie about the motion you perceive.** `--brand-animation-easing-default` is `cubic-bezier(0.16, 1, 0.3, 1)`, which completes **90% of the movement in the first third** of its duration — so the site's 0.6s scroll reveal was perceived as ~200ms and read as a snap. Lengthening the token is the fix, but the useful number is the perceived one, not the nominal one. **Measure it off the running page**: drive Edge over the DevTools protocol and sample `getComputedStyle(el).opacity`/`.transform` every 60ms. Two mechanics that cost time — headless Edge's `--dump-dom` returned nothing here (use `--screenshot`, which works), and the DevTools websocket rejects the handshake with **403** unless you pass `--remote-allow-origins=*`.

38. **A generated docs page that counts its own references cites itself as evidence.** The `/design-system` page counts `var(--token)` across the site to show each token's blast radius; counting its *own* stylesheet made `--color-decorative-orange-soft` and `--borderRadius-large` read as live when the only user was the swatch describing them. Excluding `app/design-system/` moved three tokens to correctly "unused". Same session, same shape one layer down: a guard comparing *parsed* tokens against *declared* tokens can never fire, because both sides run the same comment-stripping model and agree by construction — it was a tautology that looked like a safety net. The real invariant was `/*` vs `*/` **balance**, which does fire (verified by unterminating a comment and watching the build fail). 39. **`AELLO_CONFIG_DIR` is how you test a multi-machine flow without touching the real config.** `config::config_dir()` honours it before falling back to `ProjectDirs`, so `AELLO_CONFIG_DIR=<tmp>/cfgA` gives the real binary a throwaway `config.toml` — two of them plus two checkouts of one `git init --bare` remote simulate two machines end to end, with `aello add`/`login`/`restore` all real and the user's 39 blueprints untouched. The other half of the trick: **`aello run <bp> -- --version`** places the env and then launches `claude --version`, which exits immediately — so you can exercise `place()` (mirroring, scaffolding, hook registration) without an interactive session or burning tokens. This is what verified the two-device round trip on 2026-08-08; doing it against the real config would have polluted it, and doing it with unit tests alone would have missed that `git` normalises what the mirror carries (#40).

40. **Byte-comparing a git-tracked file against a gitignored one is a false-difference machine.** `aello restore` compared `claude-internal/<name>/persona.CLAUDE.md` with `<env>/CLAUDE.md` byte-for-byte to decide whether to report a diverged persona. But `* text=auto` (which aello's own `github` role scaffolds into every project) stores the tracked snapshot LF and checks it out with the platform's newlines, while the env dir is gitignored and keeps whatever wrote it — so two files with identical text differ in bytes on any machine whose checkout disagrees with the writer, which is exactly the Windows↔Linux case the command exists for. Measured on a real repo: it printed "the persona differs, run `aello persona`" for a file it had itself just copied. Compare `s.replace('\r', "")`, and remember the general rule — **anything that crosses git and something git does not touch cannot be compared as bytes.**

41. **Simulating git's newline conversion by replacing `\n` with `\r\n` double-converts, and the bad test agrees with the bug you are hunting.** First attempt at measuring #40 replaced `\n` → `\r\n` in the snapshot without checking what it already had — the file was *already* CRLF (the bundled persona template is baked in by `include_str!` from a Windows checkout, so `<env>/CLAUDE.md` is CRLF too), so the replace produced `\r\r\n`, which git never emits. It "confirmed" the bug for the wrong reason and would have confirmed it even if the code were correct. **Print the bytes of both sides before drawing a conclusion** (`env.read_bytes()[:20]`), and construct the mismatch you actually mean: one side LF, one side CRLF, same text. Same family as #30 — a test that passes (or fails) for a reason you did not predict is not a measurement.

42. **`*.HANDOFF.md` in `.gitignore` is unanchored, so it matches at every depth — including inside the tracked mirror.** Extends #29. When the handoff needed to reach a second machine, the obvious design was to snapshot it into `claude-internal/<name>/` under its own name; `git check-ignore -v` says `claude-internal/TechnicalDirector/TechnicalDirector.HANDOFF.md` **is ignored**, so that snapshot would have been committed by nothing and noticed by no one — the exact silent-empty-result shape this repo keeps hitting. The mirror copy is therefore lowercase **`handoff.md`**, which `git check-ignore` confirms is not matched. 43. **NTFS *file tunneling* re-uses a deleted file's CreationTime when the same name reappears within ~15 seconds — so a recreated file can look older than the thing that recreated it.** Hit while proving that an isolated Cline run writes `~/.cline/cli-node-extra-ca-certs.pem` into the shared tree: I deleted the file, re-ran the probe, and `CreationTime` came back as the *original* 17:51:58 rather than the moment of the run.
