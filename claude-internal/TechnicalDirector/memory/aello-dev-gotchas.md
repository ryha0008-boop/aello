Two non-obvious things when developing/testing aello on Windows:

1. **`cargo install --path . --force` fails with "Access is denied" when any `aello.exe` is running** (live TUI/run sessions hold the binary). Fix: rename the running exe out of the way first — `Rename-Item ~/.cargo/bin/aello.exe aello.exe.old-<tag> -Force` — then `cargo install`. Windows allows *renaming* a running exe (just not overwriting/deleting). aello's startup sweep cleans `aello.exe.old*` later. Alternatively use `aello update` (it does the rename trick internally, pulling the released binary).

2. **Claude Code print mode (`claude -p`, i.e. `aello run <bp> -p "..."`) does NOT inject persistent project memory** (`<env>/projects/<slug>/memory/MEMORY.md`). Only interactive sessions load it. Verified by control test: even an env with memory definitely loaded (TechnicalDirector) reports "NO MEMORY LOADED" under `-p`. So you can't use `-p` to verify a memory-seeding feature — verify by path-identity instead (the seeded `projects/<slug>/memory/` dir must match the slug Claude writes its session `.jsonl` into; `sessions::encode_project_path` produces it). See [[aello-ci-release]].

3. **`gh issue view <n>` fails on this machine** with `authentication token is missing required scopes [read:project]` (and sometimes API timeouts) — the default view tries to fetch linked project data. Read issues with `gh issue view <n> --json title,body -q '.title + "\n\n" + .body'`, and `gh issue list` for the list. Commits with `Closes #n` trailers still auto-close the issues on push regardless.

4. **A new universal skill (`/handoff`, `/twosentences`, `/note`, …) does NOT backfill to already-placed envs.** `place()` re-seeds the universal skills on every run, but only for the env being placed, and only via the *installed* binary — so existing env dirs across the machine stay stale until you `aello run` each one again with a freshly `cargo install`ed binary. The user runs ~29 envs across ~20 repos and does NOT want to re-run them. When you add a universal skill, **seed it directly** into every existing env: `find /c/Users/H -maxdepth 6 -name .aello.toml`, derive the blueprint name from the `.claude-env-<name>` dir, and write `<envdir>/skills/<skill>/SKILL.md` with the name substituted (the per-blueprint name is woven into the skill body). Design note for `/note`: it **overwrites** `<target>.NOTE.md` (single current note), not appends — the user reads a note the moment it's left, so accumulation is unwanted.

5. **`aello update` cannot deliver work that lives on a branch — and it fails silently.** It fetches the latest *release*, and CI only builds on pushes to `main`. Testing a branch feature means `cargo install --path . --force` (see #1), not `update`. The trap is that the released version can be *higher* than the branch build (2026-08-01: installed 0.1.52 from a release vs 0.1.51 on `launch-prep`), so `aello update` looks like it upgrades while actually removing the feature you wanted to test. Check `aello <cmd> --help` for the new flag, not the version number. After `cargo install`, the local build's lower version is cosmetic — CI renumbers on merge.

6. **Print mode fires hooks even though it skips memory.** Complementing #2: `aello run <bp> -p "..."` does load the persona and does run `Stop`/`SessionEnd` hooks, so it's a valid way to place an env and exercise hook behaviour headlessly. Only persistent *memory* injection is missing.

7. **Claude Code's cwd→projects-dir encoding folds EVERY non-alphanumeric char to `-`, not just separators.** Verified empirically 2026-07-08: a real folder `…\work\human_behavior` is stored by Claude under `~/.claude/projects/` as `…-work-human-behavior` (underscore → hyphen; case preserved). So the rule is `replace([^A-Za-z0-9], '-')` — spaces and `_` fold too, not only `\ / : .`. aello's `sessions::encode_project_path` previously only folded `\ / : .`, so for any project path containing `_`/space it pointed seeded memory + `--resume` at a dir Claude never reads (silent no-op). Fixed on branch `audit-fixes-2026-07-08`. This is the ground truth behind the path-identity requirement in gotcha #2. See [[aello-architecture-decisions]].

8. **aello's own config is at `%APPDATA%\aello\config\config.toml`** — note the extra `config/` level that `directories::ProjectDirs` adds on Windows. It is not in `~/.config/aello/`, not in `%APPDATA%\aello\`, and a `find` over the obvious places misses it entirely; this cost several commands on 2026-08-02. That file is the only place capabilities are recorded, so it is what you check when you need to know what a blueprint actually has.

9. **A `SessionStart` hook can inject text into the new session, and it works** — verified end to end on 2026-08-02, not assumed from docs. Print `{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": "..."}}` to stdout and Claude reads it as context. Confirmed by planting a note containing a nonsense codeword, running `aello run <bp> -p "what is the codeword?"`, and getting the codeword back. This is what makes `/handoff` and `/note` actually self-consuming (see [[aello-voice-capability]] for the hook-file layout). Worth remembering because the contract is external to this repo and easy to get subtly wrong — plain stdout is also accepted for SessionStart, but the JSON form is explicit.

10. **After hand-backfilling env dirs, `cargo install` immediately — an older binary silently undoes the work.** `place()` rewrites the bundled files (hook scripts, universal skills) into `<env>/hooks/` on **every** run, unconditionally, so a stale `~/.cargo/bin/aello` overwrites a fresh backfill with the version it was built from, on the next `aello run` of that env, one env at a time. Complements #4: #4 is why a backfill is needed at all, this is why it doesn't stay done. The tell is nasty — most envs stay correct while whichever ones you happen to run go quietly stale. The reusable script pattern (glob `Desktop/*/**/.claude-env-*` filtered to dirs holding `.aello.toml`, byte-compare each bundled file, `--apply` to copy, then a `--verify` pass that actually *runs* the copy and checks what it reports) is carried forward per bump — latest copy `…\058e76d8-…\scratchpad\backfill_hookv5.py`, see [[aello-voice-capability]] #11; 39 envs on 2026-08-02, up from 38 the day before.

11. **This machine can screenshot a web page without downloading a browser.** Playwright *browsers* already sit at `%LOCALAPPDATA%\ms-playwright` (several chromium revisions), but the `playwright` npm package isn't installed in any project — and a fresh `npm i playwright` then fails at launch with "Executable doesn't exist at …chromium_headless_shell-<newer rev>", because the new package expects a revision that isn't there. Don't run `npx playwright install` (~150 MB); install the package into the scratchpad and pass `executablePath` to a revision that does exist, e.g. `chromium.launch({ executablePath: 'C:\\Users\\H\\AppData\\Local\\ms-playwright\\chromium-1228\\chrome-win64\\chrome.exe' })`. Second trap: `fullPage` screenshots of a page using IntersectionObserver scroll-reveals come out with **blank mid-page sections** — jumping straight to the bottom and back never intersects the middle. Step the scroll down in half-viewport increments first, then capture.

12. **Resuming through aello is a full `aello run` — `place()` runs first.** `run_blueprint` calls `project::place()` unconditionally (`main.rs:551`) *before* it even interprets `--resume` (line 567); resume only changes an argument passed to `claude`. So `aello run <bp> --resume` (and the TUI) re-seeds skills, rewrites the bundled hook scripts, and self-heals `settings.json` exactly like a cold start — which makes "exit every session and relaunch" a valid way to roll a template or hook change across the fleet. It does **not** hold for resuming from *inside* a running Claude session, or for `claude --resume` run directly: neither touches aello, so neither picks anything up. Complements #10 — this is the mechanism by which a stale installed binary reaches an env.

13. **Backfilling a *hook* is two parts; backfilling a script is one.** The voice backfills (#10) are pure file copies, so the reusable script pattern covers them. A hook is different: `hooks/<x>.py` must be written **and** registered as an entry in that env's `settings.json`, because `settings.json` is written once at first placement and never clobbered — `ensure_own_hook` self-heals it, but only when that env is next placed. On 2026-08-02 the SessionStart hook was in 2 of 39 envs for this reason. Key on aello's **script name**, not the event key (a third-party hook on the same event must not block the heal), and check both halves independently: the audit that day found 6 envs registering `session-end.py` with no such file on disk (a hook that fires and fails) and 2 envs with no `Stop`/`speak.py` entry at all (silent, against the "every env speaks" invariant). Script: `…\39e11acf-…\scratchpad\backfill_hookregs.py` — covers all four owned hooks, writes missing scripts, refreshes stale ones, and verifies both halves.

15. **No persona should carry a TL;DR section — and a *generated* one must not reintroduce it.** The experiment recorded here on 2026-08-03 (the instruction moved out of the global persona onto a hand-registered `UserPromptSubmit` hook in TechnicalDirector only) **ended the same day and shipped**: `c34faf9` bundles `src/hooks_user_prompt_submit.py`, `place()` registers it, and all 41 envs were backfilled — so the TL;DR rule now arrives on every prompt, everywhere, along with conciseness and anti-sycophancy. `injects_tldr_per_turn` makes `ensure_tldr_instruction` skip the persona append whenever that hook is registered, so a cleared persona stays cleared. Consequences: the ~40 envs placed earlier keep a duplicate copy in their personas (harmless, and not worth editing a user-owned file to remove), and `/regenerate-claude-md` is instructed not to write the section — nor to restate the other two rules, which would cost context on every turn for nothing. Enforcement never lived in the instruction anyway: `speak.py` exits 2 on a response with no `TL;DR:` line and asks for one, so the worst case was ever an extra round trip. See [[aello-voice-capability]].

16. **`claude_md` is now `coder` / `none` / `custom` (or a path) — rebuilt 2026-08-03, superseding the old "absent means non-coding" reading.** The user's rule, unchanged: a project starts on a sensible day-one default and earns a custom persona once it has grown. What changed is that the states are now explicit. **`coder`** = a coding project. **`none`** = anything outside IT, blank because a coding persona there is actively wrong — blank is the right day-one state, not a permanent verdict, and a grown non-coding project earns a persona exactly as a coding one does (derived from sources-and-uncertainty for research, voice-and-revision for writing, not from tests and commits). **`custom`** = a generated persona has been accepted; `<env>/CLAUDE.md` is authoritative and `resolve` returns `None` so `place` writes nothing over it. **`sysadmin` was deleted** and its one blueprint migrated to `custom` — the env already held the text, so `coder` would have claimed text it does not have. `Config::migrate_personas` folds absent → `none` and `sysadmin` → `custom` on every load, idempotent, beside `migrate_roles`. **Paths are still accepted and deliberately not in the picker**: ShellyCore, Cleaning3DDev and EnvRunner2–4 point at files the user maintains, and EnvRunner2–4 *share* one `driver.CLAUDE.md`, so converting them to `custom` would freeze three copies and end the sharing silently — propose edits to that file by path, and say it lands in more than one env. Generation lives in **`<env>/persona.gen`** (`gen1 2026-08-03`), a sidecar because config and `.aello.toml` are both rewritten from a struct on every `place`. Install with `aello persona <name> --from <file> --project <dir>`, never by hand-editing `config.toml` — `Config` is serialized from its struct, so any key written by something else vanishes on the next save. `/regenerate-claude-md` proposes; `/regenerate-claude-md-accept` installs. **Exercised end to end 2026-08-03: TechnicalDirector is the first `custom` env, `gen1 2026-08-03`.** One thing that surfaced only by running it — an env's `CLAUDE.md` can already be heavily hand-edited (this one was `+58/−9` against the stock template) while config still says `coder` and no `persona.gen` exists, because `place` never clobbers a persona. Nothing records such an env as customised, so a fleet inventory counts it as stock; check the file against `templates/coder.md` rather than trusting the config value. See [[aello-architecture-decisions]].

18. **`Cargo.lock` re-dirties itself within seconds — a background rust-analyzer rewrites it, not your build.** Long assumed to be "every `cargo build` dirties it" ([[aello-ci-release]]), which is only half true: on 2026-08-03 `git checkout -- Cargo.lock` was measured reverting the `aello` version line to the committed 0.1.51 and finding it back at the manifest's version **2 seconds later with no cargo command run**. Something is watching the manifest. The practical consequence is that `git restore Cargo.lock && git pull --rebase` **cannot** work — the file is dirty again before the rebase starts, and the rebase aborts with "cannot rebase: You have unstaged changes". Use **`git pull --rebase --autostash`**, which stashes and restores atomically. Also: a `git stash` taken while this is happening contains `Cargo.lock`, so a later `git stash pop` silently re-dirties the tree — and a `pop` that fails on a dirty tree keeps the stash, so check `git stash list` before assuming edits were lost (they were not; that is how the v0.2.0 release.yml edit survived).

19. **The docs site is generated from `docs/`, so a doc edit redeploys the website.** Shipped 2026-08-03: `site/lib/docs.ts` reads `../docs/*.md` at build time and `site/app/docs/` renders them, so `docs/` now has **three** readers — the binary (`docs.rs`), the TUI (`?`) and the web — from one source. `.github/workflows/pages.yml` triggers on `site/**` **and `docs/**`** for exactly this reason. Two things to know: the site build needs `NEXT_PUBLIC_BASE_PATH=/aello` for the GitHub Pages *project* path (read by both `next.config.ts` and `lib/docs.ts`, unset locally so `npm run dev` stays at the root); and the landing page's Workflows section resolves its anchors from `docs/workflows.md`'s rendered headings and **throws at build time** if a heading is renamed, rather than shipping a dead `#anchor`. `actions/configure-pages` needs `enablement: true` or the first run fails with "Get Pages site failed" — the default is to fail rather than switch Pages on.

20. **`.gitignore` does nothing to a file git is already tracking — adding the rule is only half the fix.** On 2026-08-03 `AUDIT-2026-07-08.md` was found still on GitHub, ~6 weeks after commit `dec3fd9` added `AUDIT-*.md` to `.gitignore` specifically to honour the audits-never-go-to-GitHub ruling. The rule was real, the intent was right, and the file was published the whole time, because it had been committed first (`1ec8156`). `git check-ignore -v <file>` reports a tracked file as **NOT ignored**, which is the cheap way to catch this. The fix is `git rm --cached <file>` (keeps it on disk; the ignore rule then applies) plus a commit. Same shape as this project's other characteristic bugs: a guard was added and nobody measured whether it caught anything — `VERSION` and `.github/workflows/version.yml` got the same treatment in the same commit and *were* untracked properly, which is exactly why nobody noticed the third one wasn't. When adding an ignore rule for something that already exists, verify with `gh api repos/<o>/<r>/contents/<path>` rather than trusting the rule.

21. **Python's `glob` never matches a leading dot with `*` — so a fleet scan over `.claude-env-*` silently returns nothing.** Cost a false "0 placed envs found" on 2026-08-03, which read exactly like a correct answer. `os.path.join(root, "*", ".aello.toml")` finds nothing, because the env dir component `.claude-env-X` starts with a period and `*` skips dotted names; spelling the dot literally (`".claude-env-*"`) fixes it and found 41. Bash `find` has no such rule, which is why the same sweep works there and is the safer default. Same failure shape as the rest of this codebase: no error, an empty result, and a conclusion drawn from it.

22. **An aello older than 0.2.8 breaks on a migrated config.** `claude_md` now holds `none` or `custom` for most blueprints, and a pre-0.2.8 `templates::resolve` treats an unknown name as a *file path* — so it fails with "not a built-in template or a readable file" and the launch aborts. Deliberate (a persona that silently vanished was the worse bug), but it makes an old binary a hard stop rather than a degradation. Same class as gotcha #4's pre-0.2 hazard: the config migrates forward on every load and nothing migrates back. The migration only *persists* when aello next saves — **and on this machine it has now saved** (2026-08-03, the first `aello persona` run): eight blueprints went from an absent key or `sysadmin` to `none`/`custom` in `config.toml` on disk, in the same write. So the hazard is no longer hypothetical here; any aello older than 0.2.8 is now a hard stop on this config, not a degradation. Back the file up before any command that writes it — a restore is how an earlier real-config test got undone.

24. **Mining contextdb: the user's own words are in two places, and printing them on Windows crashes.** A record is `<contextdb>/<project>/<blueprint>/<ts>_<session>_end.jsonl`, one JSON object with keys `agent`, `handoff`, `kind`, `session`, `timestamp`, `transcript`, `trigger` — the `handoff` field holds the whole `/handoff` note, which is the durable summary. The *unsummarised* user turns are only in `<ts>_<session>_transcript.jsonl`, which is a recent addition, so most sessions have a handoff and no transcript (TechnicalDirector on 2026-08-03: **21 end records over 5½ weeks, 1 transcript**). Filter transcript lines on `type == "user"` and drop blocks that are tool results or start with `<` — otherwise hook injections and `<system-reminder>` blocks swamp the real turns. **The trap:** Python printing that text to a Windows console dies with `UnicodeEncodeError: 'charmap' codec can't encode character '→'` partway through, so you get a *partial* dump that looks complete. Redirect to a file with `PYTHONIOENCODING=utf-8` and read the file. Also note a thin archive proves nothing on its own — check `settings.json` for the `SessionEnd` registration first (#13), since that hook only reached most envs on 2026-08-02. See [[aello-contextdb]].
