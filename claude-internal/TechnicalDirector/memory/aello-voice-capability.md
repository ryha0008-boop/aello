aello's `voice` capability (added 2026-08-01) vendors its TTS hook from **revoiced**, a separate project of the user's. The design rationale lives in aello's `CLAUDE.md` + `docs/capabilities.md` — this note is only the things the repo can't tell you.

1. **revoiced is at `C:\Users\H\Desktop\structuredwork\revoiced`** (github.com/ryha0008-boop/revoiced), developed by its own aello env `RevoicedMainDev`. aello vendors **five** files from `revoiced/`: `speak.py`, `duck.py`, `focus.py`, `notify.py`, `win_audio.ps1`. The rest (`serve.py`, `action.py`, `kie.py`, `launch.py`, `web/index.html`) is the voice station and stays in revoiced.

2. **The voice station is `station.cmd` at the revoiced repo root** (not in the `revoiced/` package dir — easy to miss), which pins port 8778 → <http://127.0.0.1:8778>. Running `serve.py` directly defaults to `--port 0` and picks a random one. There's a "Voice Station" shortcut on the Desktop pointing at it. It's how voice presets are managed; the vendored hook only reads the pool it writes.

3. **`%LOCALAPPDATA%\revoiced\state.json` is the contract boundary** between the two projects, not an implementation detail of either. aello's `voice.rs` writes `global` + `projects` and the `run/stop` token directly; revoiced owns `presets`, `leases`, `duck`. Verified both directions 2026-08-01: a project mute written by `aello voice mute --project` was read back by `speak.py --status` with an identical path key. If either side starts rewriting the file wholesale instead of preserving unknown keys, that breaks silently. **Both sides now hold the same two rules, as of 2026-08-04**: stage through a *per-process* temp file (a shared fixed `state.tmp` let two writers interleave into one file and rename the result into place), and **never write over a `state.json` that cannot be parsed** — reading a half-written file as empty defaults and persisting them is what turned one interrupted write into a permanent loss of the pool and every lease. aello's `read_state` did exactly that until `596806f`; absent still reads as `{}`, unparseable now errors with the path. A guarantee that holds in only one of two writers does not hold.

4. **`edge-tts` is installed globally on this machine** (`…\Programs\Python\Python314\Scripts\edge-tts.EXE`), not only in revoiced's `.venv`. That's why vendored copies in arbitrary env dirs still get real Edge neural voices rather than falling back to the SAPI system voice — the fallback path is otherwise easy to mistake for "working".

5. **How to verify voice without an interactive session.** `aello run <bp> -p "..."` places the env *and* fires the `Stop` hook — print mode doesn't load persistent memory ([[aello-dev-gotchas]] #2) but it does load the persona and run hooks, so the TL;DR gets written and spoken. The receipt is `%LOCALAPPDATA%\revoiced\history.jsonl`: each entry records `project`, the `voice` preset that spoke, the text, and the `audio` mp3 path. An entry naming a real preset means edge-tts synthesis worked; `"system fallback voice"` means it silently fell back to SAPI.

6. **Verified working end to end 2026-08-01.** A fresh `voicetest` project spoke its TL;DR aloud using preset `negras`, while the revoiced env minutes earlier had `Andrew calm` — i.e. the per-session leasing really does give concurrent envs different voices. The generated `settings.json` contained `$CLAUDE_CONFIG_DIR/hooks/speak.py` in both `Stop` and the second `SessionEnd` group, with no absolute path anywhere in the file.

7. **Existing envs do not adopt hook changes on their own.** The self-heal (`sync_voice_hooks`) only runs inside `place()`, i.e. on the next `aello run` of that env, and only via a freshly `cargo install`ed binary — the same constraint as universal skills in [[aello-dev-gotchas]] #4. It *replaces* a hand-wired entry rather than adding beside it, so migration doesn't double-speak, but each env still has to be re-run once. See [[aello-architecture-decisions]].

8. **The voice stopped being a capability on 2026-08-02 — every env speaks, unconditionally.** The user's reasoning: they would never want a project mute, and if they did they would mute it at runtime. So `--voice`/`--no-voice`, the TUI row and the wizard question are gone, `Capabilities` is five bools, and `sync_voice_hooks` has no deregister branch. Before this, only a blueprint with `voice = true` ever got a vendored hook (exactly five did), which is why ~42 envs were still hand-wired to the absolute path `…/structuredwork/revoiced/revoiced/speak.py` and quietly stayed that way — that asymmetry confused two sessions in a row, so do not reason from an old note about it. **All aello-placed envs were backfilled by hand the same day** (38 then, 39 by that evening), verified wired with zero absolute paths left. Config lives at `%APPDATA%\aello\config\config.toml` — note the extra `config/` level, `find` in the obvious places misses it.

9. **Vendor all five. The old "vendor three, never five" rule was wrong and cost two hours of dead notifications on 2026-08-02.** `speak.py` guards the `focus`/`notify` imports (`try` / `ImportError` → `SimpleNamespace` stubs, upstream `a86023a`), so a three-file copy speaks perfectly while `notify`'s stub returns `False` from `show()` — **no toast is attempted in any env, and nothing says so**. It was reported broken twice and measured healthy twice, because the tests ran the repo's copy (which has its siblings) rather than the env copy the hook executes. The reason once given for excluding them — `notify` registering a `revoiced://` handler under `HKCU` — **does not apply**: `register()` is only called by the station and by `notify.py`'s own `__main__`; `speak.py` calls `show()` only, which just shells `win_audio.ps1 -Mode toast`. Fixed in aello on 2026-08-02: `place()` writes all five, all 39 placed envs backfilled, 39/39 verified.

10. **The drift check is `HOOK_VERSION`, a version and deliberately not a sha.** A module-level int near the top of upstream `speak.py`, bumped only when one of the five hook-path files changes (station work leaves it alone, so a mismatch always means real drift on code you run). aello records it in `project.rs::HOOK_VERSION` (currently **11**; 6 added prompt capture, 7 and 8 fixed it — both bugs found from this side; 9, 10 and 11 fixed the ducking damage, and 10 was itself damaging — see #16); two unit tests fail if a re-vendor moves the scripts without the constant, and `aello voice status` prints it. Verify an env with `python <env>/hooks/speak.py --hook-version`, which prints the bare number **before any optional import**, so even a partial copy answers; `--status` also reports it but leads with the `MISSING` list, so use it when you want to know *what* a copy lacks. **Never record a sha instead**: revoiced's CI commits a `VERSION` bump on every push to main, so local work always rebases onto that bot commit and unpushed shas get rewritten. That is what ate `a86023a`, and it ate two more shas inside one evening.

11. **A machine-wide backfill of the 39 envs is the routine part of every re-vendor.** 3 → 4 → 5 all landed within one evening of 4 being introduced, and 6 → 7 → 8 inside two hours the next night, so this is a recurring chore, not a one-off. Script: `…\39e11acf-…\scratchpad\backfill_hookregs.py` (dry-run by default, `--apply`; refreshes any stale vendored script **and** heals the four hook registrations), paired with `verify_hookv6.py`, which asks every copy `--hook-version` and takes the expected number as an argument — so a bump changes an argument, not the script. Order matters: `cargo install --path . --force` **first**, then backfill — a stale installed binary rewrites the bundled hooks on every `place()` and quietly undoes a backfill one env at a time ([[aello-dev-gotchas]] #10).

12. **`notify.register()` writes two independent halves, and only one of them is a vendored copy's to claim.** The AppUserModelID is a *name* — what makes a toast appear at all — and any copy may claim it. The `revoiced:` protocol is a *promise to run something*: it points at an `action.py` beside whichever copy registered it, and an aello env's `hooks/` has none (the five hook-path files are vendored, the station is not). Until upstream `9d085c8` `register()` wrote both together, so calling it from an env would have repointed both toast buttons at a missing file on every launch. aello shipped a `reg query` guard for exactly one release (v0.1.61) and dropped it once upstream split the halves; `voice::ensure_notify_registered` now just runs `--register` unconditionally. **Do not gate the call behind a marker file** — RevoicedMainDev ruled on this 2026-08-02 23:26 and the reason is the interesting part: the handler command embeds two absolute paths (`pythonw.exe` and `action.py`), so a Python upgrade or a repo move invalidates it. A marker is a cache that goes stale exactly when the truth changes, pinning the machine to a handler that no longer exists — buttons dead, silently, the same class as a vendored copy that can't tell it's behind. Re-registering every launch is self-healing, and `--register` is cheap enough to be invisible: `notify.py` imports nothing from `speak`, touches no data dir, no `state.json`, no `history.jsonl`, takes no lease. **The generalisable bit:** RevoicedMainDev verified the flag from the revoiced checkout, where `action.py` *is* a sibling — the same blind spot as testing the repo's `speak.py` instead of the vendored one. Anything in revoiced that resolves a path relative to its own file needs checking against a five-file copy in a bare directory.

13. **RevoicedMainDev has a standing invitation for field reports, and it is worth using.** Their words 2026-08-03: *"You see revoiced's hook running in 39 environments; I only ever see it in one. If a vendored copy does something that looks wrong from where you stand, a note here is worth more than a fix from me guessing. Bare facts and the command you ran are ideal."* That asymmetry is the whole value of this side of the boundary — and it is the same blind spot that keeps producing bugs in both directions: **verify against a vendored copy in a bare env dir, never the repo checkout**, where every sibling and `action.py` happens to exist. Precedent: `HOOK_VERSION` 6 shipped prompt capture that stripped `<command-args>`, so `/note <272 characters of what the user typed>` recorded as `/note`. Found by running upstream's own `user_prompts()` from a placed env's `hooks/speak.py` against a live transcript, not by reading the diff. Reported with the measurement and the generalisation (`/loop 5m /foo` → `/loop`); fixed and re-vendored as 7 inside an hour. The transferable rule: **measure it, from the copy that actually runs, and say which part is severe** — they said the severity call was worth more than the bug.

14. **The prompt-capture dedup drops a message that is a prefix of the next one, and that is a deliberate trade.** Added upstream at `HOOK_VERSION` 8 to stop an edited-then-sent ask being recorded twice (the transcript holds both the short draft and the long final). The cost RevoicedMainDev accepted and documented: a genuine second message that happens to *begin with* the first is dropped. A shortened resend is safe — walking newest-first, the longer one is already recorded and the shorter is not its prefix. Worth knowing before reading a missing line in History as a bug.

13. **The TL;DR instruction moved out of the persona onto a bundled per-turn hook, and now carries two more rules (2026-08-03).** `src/hooks_user_prompt_submit.py` is written and registered by `place()` in every env, injecting ~147 tokens on **every prompt**: be concise (no preamble/filler/hedging), no sycophancy (no opening praise or agreement, no validating an unchecked premise, no softening a finding; say plainly when the user is wrong and say "I don't know"), and end with `TL;DR: <two sentences>`. **Per turn, not per session**, because style decays — an instruction given at turn one is buried by turn eighty. **On a hook, not in the persona**, because the persona is written once and never clobbered, so editing `templates/coder.md` reaches *no* existing env, while `place()` rewrites hook scripts on every run. Started as a hand-registered experiment in TechnicalDirector that morning; bundled the same day when the user asked for conciseness and anti-sycophancy fleet-wide. The bundled script **had** to keep the TL;DR text — `place()` overwrites bundled hooks, so a version without it would have silently replaced this env's working copy and left `speak.py` nagging for a line nothing asked for. `ensure_tldr_instruction` survives as a fallback for an env that unregisters the hook by hand; envs placed earlier keep the TL;DR section in their personas *and* get it per turn (duplicated, harmless, not worth editing a user-owned file). A generated persona should **not** restate any of the three. `user_prompt_submit_hook_carries_the_three_response_rules` pins the wording.

14. **Backfilled to all 41 envs on 2026-08-03, both halves, verified by execution.** A hook backfill is the script file **and** the `settings.json` registration (see [[aello-dev-gotchas]] #13); 41 files written, 40 registrations added (this env already had one). Verified not by checking the files exist but by **running every placed copy** and parsing its JSON back: 41/41 emitted all three rules, 0 duplicate groups on a second pass, 0 envs lost their voice hook or model key. Script: `…\798bceee-…\scratchpad\backfill_upshook.py` (`--apply`, then `--verify`). Ordering matters — `cargo install` **before** the backfill, or the stale binary overwrites it on each env's next run (#10).

15. **The per-turn hook now carries FOUR rules — "never present a plan, never use plan mode" joined them 2026-08-03 — and it ships with an enforcing half.** `src/hooks_pre_tool_use.py` is a bundled `PreToolUse` hook matching `EnterPlanMode|ExitPlanMode` (`PLAN_TOOLS` in `project.rs`) that denies both; `ensure_own_hook` gained `ensure_own_hook_matching` because `PreToolUse` needs a **matcher** — an unmatched group fires on every tool call, a Python spawn per `Read` in every env. Backfilled to all 41 envs and verified, then re-verified by letting a real `aello run` re-place one: exactly **one** group survived with its matcher intact, which is the check that matters, since `ensure_own_hook_matching` keys on the script name and would have silently accepted a malformed hand-written group forever. **What is measured:** a `PreToolUse` deny does block a tool and return `permissionDecisionReason` to the model (tested against `Read` — it got the reason instead of the file), the matcher does scope it (a `Glob` in the same run never reached the hook), and a placed env does report the new rule back when asked. **What is NOT measured:** whether the plan tools emit a `PreToolUse` event at all — `claude -p` has no `EnterPlanMode` in its registry ("No matching deferred tools found") and never calls `ExitPlanMode` under `--permission-mode plan`, so **print mode cannot test this** and the check needs one interactive session. That is why a denial appends to `<env>/hooks/plan-blocked.log`: nothing reads it, and the first line to appear anywhere settles it. An empty log across envs that have obviously wanted to plan means the block never fires and the injected text is carrying the rule alone. See [[aello-dev-gotchas]] #25.

16. **A stale vendored copy can damage the machine, not merely lag — and the prescribed check finds only a fraction of the damage. Two different mechanisms have caused it, so "we fixed the ducking bug" has already been wrong once.** `HOOK_VERSION` 8's `duck.py` deleted its record of pre-duck volumes whenever it could not enumerate audio sessions (comtypes initialises COM per thread, and the station polls off its request threads, so this was the common path), after which each duck read an already-lowered volume as normal and squared it. Re-vendored at 10 and all 41 envs backfilled on 2026-08-04 — **and damage recurred the same day**, because 10 kept the record but keyed it on the **process id** while `GetAllSessions()` yields one control per *session* and one process owns several (a browser's media and notification streams). The second reading overwrote the first while both were lowered; the restore raised one and left the other down with its record already gone. Same 1.0 → 0.15 → 0.0225 → floor ratchet, needing only two sessions. Fixed at **11** (keyed on `InstanceIdentifier`, pid kept for liveness, still reads the pid-keyed records copies on 10 left behind, and `restore()` no longer runs unlocked on a merely contended lock). Re-vendored + all 41 envs backfilled and asked their own version 2026-08-04: 41/41 report 11. **The lesson is the recurrence, not either bug:** a re-vendor that fixes damage needs a *second* sweep days later, because the first sweep only proves the copies changed, not that the new copy is harmless. **The durable finding is where the damage lives.** Per-application volume persists in `HKCU\Software\Microsoft\Internet Explorer\LowRegistry\Audio\PolicyConfig\PropertyStore\<id>\{GUID}`, value **`3`** — a `VT_R4` PROPVARIANT with the float32 at **offset 8** (`04000000 00000000 <float>`); the entry's `(default)` string carries the exe path. RevoicedMainDev's prescribed check (enumerate `AudioUtilities.GetAllSessions()`, read `GetMasterVolume()`) sees **only the currently-active endpoint** and here found **1** damaged app; the registry scan across all endpoints found **7** — `firefox.exe` read a healthy 1.0 live while sitting at 0.0225 on another endpoint. So a live-session check that comes back clean is not evidence the machine is clean, which is this project's usual shape. Duck signatures are 0.15 (one duck), 0.0225 (two compounded) and the 0.01 clamp floor; **an exact 0 is not one** — the floor is 0.01 and 0.15ⁿ never reaches zero — so leave it, it is the user's own mute. Scripts: `…\ae1507b9-…\scratchpad\regscan.ps1` / `regfix.ps1` (backs up to `volume-backup.csv`) / `volcheck.py`. Verify the fix by watching a real cycle rather than reading the file: during a turn `%LOCALAPPDATA%\revoiced\run\duck.json` exists and names every app with its pre-duck volume, and a second after the line ends it is gone and every app is back at 1.0 — observed end to end on 2026-08-04. **Post-11 sweep, 2026-08-04 12:26:** 40 entries scanned, all at 1.0 except the one deliberate `0` — clean, and RevoicedMainDev's `SetMasterVolume` restore is confirmed to write through to the registry from the other side (so repair the *live* session when there is one; the registry write is only for endpoints nothing is playing on).
