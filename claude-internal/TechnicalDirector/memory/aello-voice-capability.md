aello's `voice` capability (added 2026-08-01) vendors its TTS hook from **revoiced**, a separate project of the user's. The design rationale lives in aello's `CLAUDE.md` + `docs/capabilities.md` — this note is only the things the repo can't tell you.

1. **revoiced is at `C:\Users\H\Desktop\structuredwork\revoiced`** (github.com/ryha0008-boop/revoiced), developed by its own aello env `RevoicedMainDev`. aello vendors **five** files from `revoiced/`: `speak.py`, `duck.py`, `focus.py`, `notify.py`, `win_audio.ps1`. The rest (`serve.py`, `action.py`, `kie.py`, `launch.py`, `web/index.html`) is the voice station and stays in revoiced.

2. **The voice station is `station.cmd` at the revoiced repo root** (not in the `revoiced/` package dir — easy to miss), which pins port 8778 → <http://127.0.0.1:8778>. Running `serve.py` directly defaults to `--port 0` and picks a random one. There's a "Voice Station" shortcut on the Desktop pointing at it. It's how voice presets are managed; the vendored hook only reads the pool it writes.

3. **`%LOCALAPPDATA%\revoiced\state.json` is the contract boundary** between the two projects, not an implementation detail of either. aello's `voice.rs` writes `global` + `projects` and the `run/stop` token directly; revoiced owns `presets`, `leases`, `duck`. Verified both directions 2026-08-01: a project mute written by `aello voice mute --project` was read back by `speak.py --status` with an identical path key. If either side starts rewriting the file wholesale instead of preserving unknown keys, that breaks silently.

4. **`edge-tts` is installed globally on this machine** (`…\Programs\Python\Python314\Scripts\edge-tts.EXE`), not only in revoiced's `.venv`. That's why vendored copies in arbitrary env dirs still get real Edge neural voices rather than falling back to the SAPI system voice — the fallback path is otherwise easy to mistake for "working".

5. **How to verify voice without an interactive session.** `aello run <bp> -p "..."` places the env *and* fires the `Stop` hook — print mode doesn't load persistent memory ([[aello-dev-gotchas]] #2) but it does load the persona and run hooks, so the TL;DR gets written and spoken. The receipt is `%LOCALAPPDATA%\revoiced\history.jsonl`: each entry records `project`, the `voice` preset that spoke, the text, and the `audio` mp3 path. An entry naming a real preset means edge-tts synthesis worked; `"system fallback voice"` means it silently fell back to SAPI.

6. **Verified working end to end 2026-08-01.** A fresh `voicetest` project spoke its TL;DR aloud using preset `negras`, while the revoiced env minutes earlier had `Andrew calm` — i.e. the per-session leasing really does give concurrent envs different voices. The generated `settings.json` contained `$CLAUDE_CONFIG_DIR/hooks/speak.py` in both `Stop` and the second `SessionEnd` group, with no absolute path anywhere in the file.

7. **Existing envs do not adopt hook changes on their own.** The self-heal (`sync_voice_hooks`) only runs inside `place()`, i.e. on the next `aello run` of that env, and only via a freshly `cargo install`ed binary — the same constraint as universal skills in [[aello-dev-gotchas]] #4. It *replaces* a hand-wired entry rather than adding beside it, so migration doesn't double-speak, but each env still has to be re-run once. See [[aello-architecture-decisions]].

8. **The voice stopped being a capability on 2026-08-02 — every env speaks, unconditionally.** The user's reasoning: they would never want a project mute, and if they did they would mute it at runtime. So `--voice`/`--no-voice`, the TUI row and the wizard question are gone, `Capabilities` is five bools, and `sync_voice_hooks` has no deregister branch. Before this, only a blueprint with `voice = true` ever got a vendored hook (exactly five did), which is why ~42 envs were still hand-wired to the absolute path `…/structuredwork/revoiced/revoiced/speak.py` and quietly stayed that way — that asymmetry confused two sessions in a row, so do not reason from an old note about it. **All aello-placed envs were backfilled by hand the same day** (38 then, 39 by that evening), verified wired with zero absolute paths left. Config lives at `%APPDATA%\aello\config\config.toml` — note the extra `config/` level, `find` in the obvious places misses it.

9. **Vendor all five. The old "vendor three, never five" rule was wrong and cost two hours of dead notifications on 2026-08-02.** `speak.py` guards the `focus`/`notify` imports (`try` / `ImportError` → `SimpleNamespace` stubs, upstream `a86023a`), so a three-file copy speaks perfectly while `notify`'s stub returns `False` from `show()` — **no toast is attempted in any env, and nothing says so**. It was reported broken twice and measured healthy twice, because the tests ran the repo's copy (which has its siblings) rather than the env copy the hook executes. The reason once given for excluding them — `notify` registering a `revoiced://` handler under `HKCU` — **does not apply**: `register()` is only called by the station and by `notify.py`'s own `__main__`; `speak.py` calls `show()` only, which just shells `win_audio.ps1 -Mode toast`. Fixed in aello on 2026-08-02: `place()` writes all five, all 39 placed envs backfilled, 39/39 verified.

10. **The drift check is `HOOK_VERSION`, a version and deliberately not a sha.** A module-level int near the top of upstream `speak.py`, bumped only when one of the five hook-path files changes (station work leaves it alone, so a mismatch always means real drift on code you run). aello records it in `project.rs::HOOK_VERSION` (currently **6**, from upstream's prompt-capture change); two unit tests fail if a re-vendor moves the scripts without the constant, and `aello voice status` prints it. Verify an env with `python <env>/hooks/speak.py --hook-version`, which prints the bare number **before any optional import**, so even a partial copy answers; `--status` also reports it but leads with the `MISSING` list, so use it when you want to know *what* a copy lacks. **Never record a sha instead**: revoiced's CI commits a `VERSION` bump on every push to main, so local work always rebases onto that bot commit and unpushed shas get rewritten. That is what ate `a86023a`, and it ate two more shas inside one evening.

11. **A machine-wide backfill of the 39 envs is the routine part of every re-vendor.** 3 → 4 → 5 all landed within one evening of 4 being introduced, and 6 the next day, so this is a recurring chore, not a one-off. Script: `…\39e11acf-…\scratchpad\backfill_hookregs.py` (dry-run by default, `--apply`; refreshes any stale vendored script **and** heals the four hook registrations), paired with `verify_hookv6.py`, which asks every copy `--hook-version` and takes the expected number as an argument — so a bump changes an argument, not the script. Order matters: `cargo install --path . --force` **first**, then backfill — a stale installed binary rewrites the bundled hooks on every `place()` and quietly undoes a backfill one env at a time ([[aello-dev-gotchas]] #10).

12. **`notify.register()` writes two independent halves, and only one of them is a vendored copy's to claim.** The AppUserModelID is a *name* — what makes a toast appear at all — and any copy may claim it. The `revoiced:` protocol is a *promise to run something*: it points at an `action.py` beside whichever copy registered it, and an aello env's `hooks/` has none (the five hook-path files are vendored, the station is not). Until upstream `9d085c8` `register()` wrote both together, so calling it from an env would have repointed both toast buttons at a missing file on every launch. aello shipped a `reg query` guard for exactly one release (v0.1.61) and dropped it once upstream split the halves; `voice::ensure_notify_registered` now just runs `--register` unconditionally. **Do not gate the call behind a marker file** — RevoicedMainDev ruled on this 2026-08-02 23:26 and the reason is the interesting part: the handler command embeds two absolute paths (`pythonw.exe` and `action.py`), so a Python upgrade or a repo move invalidates it. A marker is a cache that goes stale exactly when the truth changes, pinning the machine to a handler that no longer exists — buttons dead, silently, the same class as a vendored copy that can't tell it's behind. Re-registering every launch is self-healing, and `--register` is cheap enough to be invisible: `notify.py` imports nothing from `speak`, touches no data dir, no `state.json`, no `history.jsonl`, takes no lease. **The generalisable bit:** RevoicedMainDev verified the flag from the revoiced checkout, where `action.py` *is* a sibling — the same blind spot as testing the repo's `speak.py` instead of the vendored one. Anything in revoiced that resolves a path relative to its own file needs checking against a five-file copy in a bare directory.
