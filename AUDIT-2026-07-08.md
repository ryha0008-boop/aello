# aello — Whole-Codebase Audit (2026-07-08)

**Target:** `C:\Users\H\Desktop\work\aello`
**Language:** Rust (2021 ed.), single binary CLI + ratatui TUI · ~4,059 lines across 12 `src/*.rs` modules
**Method:** ground-truth harvest → 6 parallel module readers + 1 cross-module seam tracer → adversarial re-read of every high/med finding against the real code.

## 1. Summary

`aello` manages isolated Claude Code environments ("blueprints") placed into projects as `.claude-env-<name>/` dirs. It spawns `claude`/`gh`/`git` subprocesses, stores a long-lived plaintext OAuth token in `config.toml`, mirrors env config into a tracked `claude-internal/` folder, and self-updates by overwriting its own binary.

**Harvest (Phase 1) — the project is healthy:**

| Check | Result |
|---|---|
| `cargo check --all-targets` | ✅ clean |
| `cargo test` | ✅ 47 passed, 0 failed |
| `cargo clippy` | 4 minor warnings (`Iterator::last` on a `DoubleEndedIterator`; "items after a test module") |
| TODO/FIXME/HACK in `src` | none |
| Production `unwrap`/`expect` | negligible — the ~72 in `project.rs` are almost all `#[cfg(test)]`; the few prod `.parent().unwrap()` are on static paths |

The codebase is well-structured, well-tested, and well-documented (`CLAUDE.md` maps every module accurately). Findings below are **not** build breakage — they are latent correctness/security gaps that the green test suite does not exercise.

**Module map:** `main.rs` (CLI/dispatch/validation, 699) · `tui.rs` (ratatui TUI — god-file, 1332) · `project.rs` (placement/scaffold/mirror/memory, 807) · `templates.rs` (skill/persona rendering, 366) · `github.rs` (227) · `update.rs` (self-update, 128) · `docs.rs` (94) · `sessions.rs` (87) · `auth.rs` (89) · `config.rs` (83) · `models.rs` (75) · `launch.rs` (72).

**Headline counts:** 2 high · 7 med · ~16 low. Two findings are worth acting on before the next release (**#1 data-loss**, **#2 silent config downgrade**).

## 2. Confirmed bugs (severity-ordered)

### 🔴 HIGH #1 — `config::load()` silently wipes all blueprints + token on any transient read error
`src/config.rs:57-65`

```rust
match std::fs::read_to_string(&path) {
    Ok(text)  => toml::from_str(&text)...,
    Err(_)    => Ok(Config::default()),   // ← ANY error, not just NotFound
}
```

`Err(_)` collapses **every** I/O error — not just "file missing" — into an empty default `Config`. Nearly every command is a `load()` → mutate → `save()` sandwich (`cmd_add` `main.rs:252`, `cmd_remove`, `cmd_edit`, `cmd_login` `main.rs:462`, `cmd_init`, and the TUI add/edit/delete flows `tui.rs:521,529,538`).

**Trigger → impact:** on Windows, `config.toml` lives under the OS config dir where OneDrive sync, Windows Search Indexer, or an AV scanner routinely hold a transient lock (`ERROR_SHARING_VIOLATION`), and any PermissionDenied glitch does the same. If `load()` hits that lock, it returns an empty config; the very next `save()` **overwrites `config.toml` with the empty default**, permanently destroying every blueprint definition **and the non-rotating OAuth token** — no prompt, no backup. (Note: a *corrupt/malformed* TOML file does **not** trigger this — parse errors correctly propagate via `with_context`. Only non-parse I/O errors are the danger.)

**Fix sketch:** match on `e.kind()`; default **only** for `ErrorKind::NotFound`, propagate all other errors with `.context()` so callers abort instead of overwriting.

### 🔴 HIGH #2 — TUI edit silently downgrades a blueprint's model and drops a custom persona
`src/tui.rs:106-116, 500, 525-526`

The edit pickers can only represent curated values. `model_index` (`tui.rs:107`) returns `0` for any model that isn't literally `opus`/`sonnet`/`haiku`; `persona_index` (`tui.rs:115`) returns `0` for any persona that isn't a built-in name. On `AddCaps` Enter with `edit == true`:

```rust
b.model = model.clone();       // tui.rs:525 — always one of opus/sonnet/haiku
b.claude_md = persona.clone(); // tui.rs:526 — None when picker sel == 0
```

**Trigger → impact:** a blueprint created/edited via the **CLI** legitimately holds `model = "claude-opus-4-8"` (a full id `validate_model` accepts), or `model = "default"`, or `claude_md = "/path/to/persona.md"`. Opening it in the TUI with `E` — *even just to toggle one capability, without touching the model/persona steps* — pre-selects index 0 and, on save, rewrites `model` to `"opus"` (a full pinned id / the `default` alias is lost) and sets `claude_md` to `None` (**the custom persona path is silently discarded**). The next `aello run` then places a different model and no persona than the user configured. Pure silent data loss on a routine operation.

**Fix sketch:** carry the blueprint's original `model`/`claude_md` strings through the edit `Mode` and only overwrite when the user actually changes that picker; or give `model_index`/`persona_index` an "other (unchanged)" sentinel row instead of collapsing non-curated values to 0.

### 🟠 MED #3 — `rename_placed` is non-atomic → config and on-disk state diverge on partial failure
`src/project.rs:69-99` (with caller ordering `src/main.rs:370,383`)

`rename_placed` renames the env dir **first** (`project.rs:78`), rewrites `.aello.toml` to the new name (`82-86`), **then** moves the mirror — which can `bail!` if `claude-internal/<new>` already exists (`92-93`) or on any fs error. `cmd_edit` calls `config::save` only **after** `rename_placed` returns (`main.rs:383`).

**Trigger → impact:** rename to a name whose mirror dir already exists (or any fs error after line 78). The env dir is already `.claude-env-<new>` and `.aello.toml` already says `<new>`, but the `bail!` propagates through `cmd_edit`'s `?` so `config::save` never runs → **config still lists `<old>`, disk says `<new>`**. `aello run <old>` then finds no `.claude-env-<old>` and re-scaffolds a fresh env, orphaning the renamed dir. Disk and config permanently disagree.

**Fix sketch:** pre-check **both** destinations (`new_env` and `new_mirror`) exist-free before moving anything; or move the mirror first; or roll back the env-dir rename if the mirror move fails.

### 🟠 MED #4 — Config-loaded blueprint name is trusted at filesystem sinks without re-validation (path traversal)
`src/main.rs:424` → `src/project.rs:58-59`; also `cmd_remove --purge` `main.rs:270-292`

`validate_name` (`main.rs:210-218`) runs only on config **writes** (add `246`, edit-rename `336`, init `500`, TUI add `tui.rs:456`). Every **read** path re-derives paths straight from the stored name: `run_blueprint` → `env_dir(&project, &bp.name)` → `project.join(format!(".claude-env-{name}"))`, and `place`/`mirror`/`--purge`-delete likewise.

**Trigger → impact:** a name hand-edited into `config.toml` such as `../../evil` never passes the gate; at the sink it yields path components `.claude-env-..`, `..`, `evil`, **escaping the project dir** when creating/deleting the env dir and the `claude-internal` mirror — including under `remove --purge`'s delete. The same raw name is interpolated into generated `SKILL.md` YAML frontmatter (`project.rs:175/187/195` → `templates.rs`), so a name with a newline could also flip `disable-model-invocation`/`allowed-tools`. Locally-trusted input (hence med, not high), but `config.toml` is treated as trusted when it is really just a file.

**Fix sketch:** treat `config.toml` as untrusted — re-run `validate_name` at the sink (inside `env_dir`/`place`, or once in `run_blueprint`/`cmd_remove` after load). *Good news:* the classic "TUI bypasses validation" seam is **not** present — `tui.rs:456` validates on add and the TUI offers no rename. The only unguarded surface is hand-edited config content.

### 🟠 MED #5 — `validate_name` accepts Windows reserved device names
`src/main.rs:214` (sink `src/project.rs:318`)

The allowlist is `is_ascii_alphanumeric() || '-' || '_'` — purely character-based, so `CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9` all pass.

**Trigger → impact:** `aello add nul --model sonnet --github` then `aello run nul` on Windows. The env dir `.claude-env-nul` is safe (prefixed), but the github mirror calls `create_dir_all("claude-internal/nul")` — a **bare** reserved-device component — which Windows refuses, aborting `place()` with an opaque OS error surfacing only at the mirror step.

**Fix sketch:** after the char check, reject the reserved set case-insensitively.

### 🟠 MED #6 — Case-variant names collide to one env dir on case-insensitive filesystems
`src/main.rs:214`, `src/models.rs:73` (`find` is `b.name == name`), `src/project.rs:59`

`validate_name` never normalizes case and `Config::find` is case-sensitive, so `aello add Coder` and `aello add coder` both succeed as distinct config entries — but both map to `.claude-env-Coder` / `.claude-env-coder`, **the same directory** on Windows/macOS default filesystems.

**Trigger → impact:** running one then the other clobbers the other's `.aello.toml`/skills/mirror, silently corrupting state. (`rename_placed` is protected by its `new_env.exists()` check on such FSes, but `add` is not.)

**Fix sketch:** reject a new name whose lowercase matches an existing blueprint's (in `cmd_add`/`cmd_edit`), or canonicalize case at validation time.

## 3. Security (risk-surface findings)

### 🟠 MED #7 — Plaintext non-rotating OAuth token written world-readable (no `0600`)
`src/config.rs:76-81`

`save()` does an atomic temp-write + rename (good — protects against truncation) but never restricts permissions. On Linux (a shipped self-update target, `aello-x86_64-linux`) both the `.tmp` sibling and the final `config.toml` land at default `~0644`.

**Path:** `auth.rs` captures the `sk-ant-...` token → stored here → `launch.rs:37-38` exports it to the `claude` child. **Impact:** any other local user or compromised low-priv process can read the 1-year, non-rotating token from `~/.config/aello/config.toml` and impersonate the account indefinitely. The code comment (`config.rs:73-75`) shows the authors know this file "holds the only copy of the non-rotating OAuth token."

**Fix sketch:** on Unix, `set_permissions(&tmp, Permissions::from_mode(0o600))` before the rename (and `0700` on the config dir). No-op on Windows.

### 🟠 MED #8 — `aello login` echoes the token line to its own stdout
`src/auth.rs:29-36`

To surface the auth URL on a headless box, the capture loop tees **every** line of `claude setup-token`'s stdout — including the line carrying the token — to aello's stdout (`let _ = writeln!(out, "{line}")`, `auth.rs:32`), before scanning for it.

**Trigger → impact:** `aello login`/`aello init` run under any stdout capture — `| tee setup.log`, a CI job log, `script`, tmux capture, `2>&1` piping — persists the long-lived token in cleartext in that log. (The child already prints it to an interactive terminal; the incremental leak is aello re-emitting into its own *redirectable* stream.)

**Fix sketch:** redact any whitespace token matching `sk-ant-...` before echoing (reuse `extract_token`'s matcher), or stop echoing once the URL line is past.

### 🟠 MED #9 — Self-update installs a binary verified only by TLS + a 1 MiB floor — no checksum/signature
`src/update.rs:56-76`

`replace_binary(&exe, &buf)` overwrites the running executable with whatever bytes came back from the release asset URL. The only integrity check is `buf.len() < 1 MiB` (`update.rs:67`). The commit sha parsed from the release notes (`update.rs:47-52`) is a **git commit id printed for display only** — not a hash of the artifact — so it cannot and does not verify the download.

**Trigger → impact:** a compromised/hijacked release asset, a stolen GitHub token pushing a poisoned `latest`, or TLS interception → arbitrary code execution as the user on next launch. This is a genuine (if design-level) supply-chain gap; med because it presupposes GitHub-account or TLS compromise. Related minor: the download is slurped with `read_to_end` with a floor but **no ceiling** (`update.rs:62`) — a malicious endpoint can stream unbounded data and OOM the process.

**Fix sketch:** publish a per-asset SHA256 (or minisign/cosign signature) and verify `buf` before `replace_binary`; cap the read with `reader.take(N)`.

*Verified clean on the risk surface:* subprocess exit-status discipline in `github.rs` (`git()`/`gh repo create` both check `.success()` and bail); no pipe-fill deadlock/zombie in `auth.rs` (stderr inherited, stdout fully drained before `wait()`); git-attribution env vars are **not** injectable (blueprint names are `[A-Za-z0-9_-]`); `--old` binary cleanup sweep works (`main.rs:166-178`). Latent-only (behind the same trust model / upstream name gate): leading-`-` names and `--resume <id>`/`gh repo create <name>` lack a `--` end-of-options guard (`launch.rs:43`, `github.rs:66`) — harmless today because names/ids are constrained or self-supplied.

## 4. Architecture / complexity

**`tui.rs` — 1,332-line god-file (top split candidate).** Mixes state, event handling, rendering, and a hand-rolled markdown engine in one module; the clippy "items after a test module" warning is a direct symptom (render/markdown fns sit *below* `mod tests`). **Proposed split:**
- `tui/state.rs` — `App`, `Mode`, `compute_view`, `local_indices`, `model_index`/`persona_index`, `cap_toggle`/`cap_enabled`
- `tui/input.rs` — the `run_app` per-mode key match (~361-682)
- `tui/render.rs` — `draw` + all `draw_*` modals (~686-1038, 1109-1217)
- `tui/markdown.rs` — `render_markdown`/`inline`/`bullet`/`slice`/`push_text` (~1219-1332)
- `tui/mod.rs` — keep `run()`/`setup()`/`restore()`

This also moves every production item above the tests, clearing the clippy warning.

**`project.rs` — 807 lines (~470 production), cohesive but splittable.** Optional: extract `mirror.rs` (`copy_dir_all` + `mirror_env_internal` — the prune logic is self-contained and correct) and `settings.rs` (`settings_json`/`ensure_session_end_hook`/`mark_onboarded`); leave `place`/`scaffold`/`seed_memory`/`rename` in `project.rs`. Low priority — not tangled.

**`main.rs` — 699 lines.** Extract the security-critical `validate_name`/`validate_model` (+ their tests) into `validation.rs`, and the four stdin helpers (`confirm`/`prompt`/`prompt_bool`/`prompt_optional`) into `prompt.rs`, leaving `main.rs` as CLI def + dispatch + thin handlers.

**Coupling smell:** `templates::BUILTINS` is documented as the TUI picker's source of truth, but `tui.rs:66-70` hand-duplicates it as `PERSONAS`; only the `personas_match_builtins` unit test keeps them honest (`tui.rs:1044`). A build/typecheck-only workflow could ship a picker missing a newly-added persona. Fix: build `PERSONAS`' id list from `templates::BUILTINS` directly.

## 6. Coverage + blind spots

**Fully read & verified:** all 12 `src/*.rs` modules; every HIGH/MED finding was re-read against the cited lines before inclusion. `config::load`, `validate_name`, `rename_placed`, the TUI edit state machine (`tui.rs:495-539`), `sessions.rs`, and `auth.rs` were re-read personally during verification.

**Verified clean (candidates that were REFUTED / found guarded):**
- `place()` ordering — memory **is** seeded before scaffold/mirror (`project.rs:210` before `214/305`), so the mirror captures seeded memory. ✅
- Token `Option` flow — threaded correctly; `None` → env unset, launch proceeds with a user message. ✅
- `Capabilities` serde default — every consumer gates on `if caps.x`; a false-defaulted new cap degrades to "off." ✅
- `copy_dir_all` skips symlinks and only recurses `skills/` + `memory/` (never `.git`/whole env); prune logic is correct and tested. ✅
- git-attribution env injection — closed by the name charset gate. ✅

**NOT covered / out of scope:**
- The two bundled **Python hooks** (`src/hooks_post_compact.py`, `src/hooks_session_end.py`) were not audited — only their invocation contract from Rust.
- **Claude Code's real on-disk path encoding** (external to this repo) — L1's severity hinges on it and could not be resolved from local ground truth.
- `ureq` **TLS/redirect** configuration beyond defaults (network stack internals).
- The `.github/workflows/` CI YAML, `install.sh`, `migrate.md`, and bundled template `.md` personas were read only as orientation, not audited for logic.
- No fuzzing / no runtime execution of the TUI or `aello run` (read-only audit).
