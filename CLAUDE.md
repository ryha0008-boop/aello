# aello

Isolated agent environments — like Python venvs, but for AI agents. Two agents: **Claude Code** (subscription auth, the default and the one everything is built around) and the **Cline CLI** (its own metered provider key). Cross-platform (Linux + Windows x86_64; macOS from source).

## Docs — keep in sync with code changes

- `README.md` — user-facing: install, concepts, quick start, command + role reference. Update when commands or roles change.
- `CHANGELOG.md` — version history of user-facing changes. Every user-facing change gets an entry, in the same commit as the code.
- `docs/` — deeper reference, in `docs.rs::ORDER` reading order: `concepts.md` (isolation model, auth, contextdb), `roles.md` (role → scaffold/`/sync` mapping, the pre-0.2 capability migration, git attribution), `workflows.md` (task-shaped walkthroughs: first env, two agents in one repo, the session loop, rename, purge — the page to extend when a new usage pattern appears), `skills.md` (the four seeded skills in detail, manual-only enforcement, `.aello-keep`), `voice.md` (the whole TTS path: vendoring, the five files, toast identity, `HOOK_VERSION`, troubleshooting), `tokens.md` (where the counts come from, why dedup is load-bearing, what the cost and the 5h percentage do and don't claim), `cline.md` (the second agent: what a Cline env gets, what it cannot, and everything measured to establish which), `upgrading.md` (the page to point an env at the first time it meets 0.2 — roles migration, removed flags, the pre-0.2-binary hazard), `migrate.md` (migrating an existing repo onto aello: validated flow + gotchas), `development.md` (building aello itself: verification rule, re-vendoring, release process, commits), `troubleshooting.md` (failure modes and what they actually mean). **`docs/` is for developers and `README.md` is for users** — if a README section only makes sense to someone who has read the source, it belongs here instead. **`docs/` is also the in-app help**: it's embedded into the binary (`docs.rs`) and rendered by `aello docs` (CLI) and the TUI reader (`?`), so `docs/` is the single source of truth — add a `.md` and it appears with no code change. Keep these in sync with behavior.
- This file (`CLAUDE.md`) — agent/architecture notes. Maintain as the design evolves.
- `site/` — the landing page. A **static Next.js** app, entirely separate from the Rust crate: `cargo build`/`cargo test` never touch it, and it ships nothing into the binary. Its design tokens live in the `:root` block of `site/app/globals.css` — change values there, never inline in a component, and the build now enforces that rather than trusting it. The token *structure* (names, type scale, spacing, radii, motion) is transcribed from a captured GitHub design system; the *colours* are not — they were retuned to the brand, orange on near-black, and five tokens that named a hue they no longer hold were renamed with them. **`/design-system` renders the whole palette**, generated from `globals.css` at build time by `site/lib/design-system.ts` (swatches, type specimens, easing curves, per-token usage counts, measured WCAG contrast, breakpoints), so there is no second copy to drift. Three things throw during `next build`: a literal colour anywhere but `globals.css`, an `@media` width outside the documented breakpoints, and unbalanced comment markers inside `:root` — that last one because an unterminated comment swallows every declaration up to the next close and the page then reports the smaller token set as the truth, which it did once here. `npm run build` in `site/` emits plain HTML in `site/out/`. See `site/README.md`; update the page when the install steps, command list, or role table change. **`/docs` on the site is generated from this repo's `docs/` at build time** (`site/lib/docs.ts`), the same files `docs.rs` embeds — one source, three readers (binary, TUI, web), so a new `.md` needs no site change either. `.github/workflows/pages.yml` deploys to GitHub Pages on any push to `main` touching `site/**` or `docs/**`, building with `NEXT_PUBLIC_BASE_PATH=/aello` (read by both `next.config.ts` and `lib/docs.ts`, unset locally). The landing page's Workflows section resolves its anchors from `docs/workflows.md`'s rendered headings and **throws at build time** if one is missing — a hardcoded anchor rots silently, which is the failure shape this repo keeps hitting.

## Architecture

**Blueprint** — a reusable agent identity in `config.toml`: `name`, `model`, optional `claude_md` (global persona), and a `role`. Reusable across projects.

**Persona lifecycle** — `claude_md` is one of three values, plus a legacy path. A coding project starts on **`coder`**; anything outside IT starts on **`none`** (blank, because a coding persona there is actively wrong); both become **`custom`** the first time a generated persona is accepted, after which `<env>/CLAUDE.md` is authoritative and `templates::resolve` returns `None` so `place` writes nothing over it. `sysadmin` was a fourth template and was **dropped** — barely used and effectively coder with different nouns. `Config::migrate_personas` (every load, idempotent, beside `migrate_roles`) folds absent → `none` and `sysadmin` → `custom`: the one env on it already holds that text, since personas are never clobbered, so `coder` would have been a false claim. **A path is still accepted** and deliberately not in the picker — five blueprints point at persona files the user maintains and three of them share one file, so collapsing those to `custom` would freeze the copies and end the sharing silently. Generation lives in **`<env>/persona.gen`** (`gen1 2026-08-03`), a sidecar rather than a config key or an `.aello.toml` field because both of those are rewritten from a struct on every `place` and would drop it — config answers *whether* an env has a custom persona, the sidecar answers *which generation*. `aello persona <name> --from <file> [--project <dir>]` (`cmd_persona`) does all three writes together; it is the **only** command that overwrites a persona, and it goes through aello because `Config` is serialized from its struct, so a key written into `config.toml` by anything else vanishes on the next save.

**Agent** (`models.rs::Agent`) — `claude` (default) or `cline`, chosen at `add` time and fixed. `#[serde(default)]` on the field *is* the whole migration: every blueprint written before it loads as Claude, which is what it was. The split is total and everything Cline lives in **`cline.rs`** — `project.rs` and `launch.rs` stay Claude-only, because the two CLIs agree on almost nothing and a shared path would carry an `if agent == …` at every branch, where the forgotten branch writes a Claude file into a Cline env and nothing ever reads it. Env dirs: `.claude-env-<name>` vs `.cline-env-<name>`, single-sourced through `Agent::env_prefix()` (Claude's is load-bearing — 39 dirs on disk carry it, so the *new* agent got the new prefix) and reached through **`Agent::env_dir(project, name)`**, which is the one place a path to an env dir is built. `project::env_dir` is Claude-hardcoded and five call sites used it without asking the blueprint: `remove --purge`, `edit --rename`, and the TUI's local filter / session list / delete warning. Each addressed a directory that does not exist for a Cline blueprint, found nothing, and said nothing — a `.cline-env-<name>` holding the plaintext provider key survived its own purge. That is the shape the whole split is meant to prevent, so a new site that needs an env dir asks the enum. Isolation is `CLAUDE_CONFIG_DIR` vs the `--config`/`--data-dir` **flags**; persona is `CLAUDE.md` vs `<env>/config/rules/*.md` (Cline ignores `CLAUDE.md`); auth is one shared subscription token vs a per-token-billed provider key. **A Cline env gets no voice, no per-turn rule injection and no contextdb** — measured, not skipped: of `TaskStart`/`TaskComplete`/`SessionShutdown`/`UserPromptSubmit`/`PostToolUse`, only `TaskStart` fires, only from `<config>/hooks/` (a `--hooks-dir` copy fired **nothing**), and its payload is identifiers with no prompt and no response, so there is no end-of-response event to speak from. The four response rules survive as a rules file, since Cline re-sends rules in the system prompt every request — the same non-decaying property the per-turn hook buys. `<config>/rules/` being the read location was measured with a canary against three candidates and beat `<data>/rules/` and the project `AGENTS.md`.

**The Cline credential is installed by `cline auth`, never by writing `providers.json`** — the one trap in this area, and it half-worked, which is worse than failing. Hand-writing the file placed the env, launched the run and reached the provider, which returned an error that read like a bad key; what actually happened is that **Cline rewrote the file on its next run and dropped `apiKey` outright**, so the request carried no credential. Measured by diffing either side of a run; a `cline auth` key survives the same run untouched. `cline::ensure_credential` therefore shells out on **every** run — not behind a marker, since the key can change in `config.toml` and a marker would go stale exactly then. `aello login` asks which agent (or `--agent`); the two logins are stored separately (`oauth_token` vs `[cline]`) and neither is inferred from the other. **`.cline-env-*` is gitignored unconditionally** — because it holds the API key in plaintext, so a standalone blueprint's key leaks exactly as well as a maintainer's. This used to read "NOT role-gated like `.claude-env-*`, since a Claude env holds no secret"; **both lines are unconditional now** and that rationale was false (see Roles below — a Claude env with no shared token holds its own `.credentials.json`). **Known upstream limit:** Cline's `claude-code` provider authenticates on aello's shared token and then cannot use tools at all — every call is rejected before execution ("the Claude Code CLI executes its own tools; AI SDK tools cannot be auto-bridged"), unmoved by `--auto-approve true`, `bypassPermissions` or a seeded `.claude.json`. So a Cline env that edits files needs a metered provider. **A Cline env does get the rest**, all of it through `<env>/config/rules/*.md`, which Cline re-sends in the system prompt every request (the same non-decaying property the per-turn hook buys a Claude env): the **persona** (same bundled templates — `--claude-md coder` works; `none` *removes* an existing `persona.md`, and that branch matters because rules apply every request and nothing else would ever clear it), the four **commands**, and a **memory**. Both of the last two are instructions the agent follows, not hooks aello enforces — weaker than the Claude equivalents, and the docs say so. **Cline has no user-defined slash commands** (measured: `/canary` with a workflow *and* a skill in all four candidate locations came back as prose; the binary's only slash commands are connector built-ins `/abort`/`/clear`/`/exit`/`/start`/`/whereami`, and Cline's own skills/workflows are plugin artifacts under `<workspace>/.cline/<plugin>/`), so `aello.md` **routes** them by naming each against its `SKILL.md` absolute path — matching a **prefix**, not an exact message, for the reason below. **Verified end to end** against a real OpenRouter model 2026-08-06: `/sync now` opened the memory index and looked for `AGENTS.md`, `/handoff please` wrote a name-prefixed `<name>.HANDOFF.md`. Real slash commands would mean shipping a **JavaScript plugin** — the TUI's `/` menu is five built-ins plus `listRuntimeCommands()` from installed plugins, and `cline plugin install` rejects a markdown folder with "No plugin entry files found"; it also installs to `<project>/.cline/plugins`, workspace-scoped, so one plugin would be shared by every env in a repo. A node dependency plus a hole in the isolation model, for cosmetics. **Cline has no memory system either** (`memory-bank`/`memoryBank`/`cline_docs`/`MEMORY.md`/`rememberThis` all absent from the binary; the one `auto-memory` hit is Claude Code's embedded settings schema), so aello seeds `<env>/memory/MEMORY.md` **once, never clobbered**, plus a rule to read and maintain it. **Cline `/sync` has no git step** — memory then the project's `AGENTS.md`, and stop. **Paths written into rules are forward-slashed** (`slash()`): the templates join with `/` while Windows `Path` yields `\`, which produced `C:\…\skills/sync/SKILL.md` — functional but unmatched by anything, which is how a test caught it. **Cline rejects ANY one-word prompt**, `/sync` and the other three included, so `run_cline` refuses one with the real reason before launching and the documented form is `-p "/sync now"`. ⚠️ **This nearly shipped wrong**: an early test showed `-p "/twosentences"` apparently working, but Git Bash had rewritten it to `C:/Program Files/Git/twosentences` — which contains a space, so Cline accepted it and the model *guessed* the skill from the path. Set `MSYS_NO_PATHCONV=1` when testing a leading-slash argument from a POSIX shell on Windows, or measure the wrong thing. `aello edit --model` also had to stop applying Claude's model rules to a Cline blueprint (`add` was already right). TUI: `a` opens the agent picker **first** (`Mode::AddAgent`), then name, then a **free-text** model step for Cline (`Mode::AddClineModel` — provider model ids have no list to curate); the chosen agent rides on `App::add_agent` rather than being threaded through five Mode variants, and **edit never offers the picker** since an agent is fixed at creation. See `docs/cline.md`.

**Roles** (`models.rs::Role`) — one of `maintainer` / `contributor` / `standalone`, chosen at `add` time. `Role::caps()` expands it into the internal five-bool `Capabilities` struct that `project.rs` and `templates.rs` still work in, so a role is *only* a restriction on which combinations are offered — placement and `/sync` generation are unchanged. maintainer = all five; contributor = `github` + `changelog`; standalone = none. `Capabilities::any()` still gates seeding `/sync`. **Why three and not five checkboxes:** the flags were never independent per repo — one blueprint holds everything, the rest hold git duties only — and 32 of the 32 unused combinations were pure surface area. **Migration:** pre-0.2 configs carry `[blueprints.caps]`; `Config::migrate_roles` (called from `config::load`, every load, idempotent) folds it via `Role::from_caps` — prose caps (`project_md`/`docs`/`readme`) → maintainer, git-only → contributor, none → standalone — and `legacy_caps` is `skip_serializing`, so the old key disappears on the next save. Run on every load rather than behind a marker so a restored backup heals itself instead of silently loading as standalone. **`voice` was a sixth and is not any more** — every env speaks unconditionally, so there is no flag, no TUI row and no `--no-voice`; silence is `aello voice mute` at runtime. Serde ignores a leftover `voice = …` in an existing config and the next save drops it. **The `.claude-env-*` gitignore line is no longer role-gated** — every placement writes it, as the Cline side always has. It sat inside `if caps.github` as tidiness, on the premise that a Claude env holds no secret because auth is an env var; false whenever no shared token is configured, since Claude Code then writes its own `.credentials.json` into the env dir (`run_blueprint` probes for exactly that file), and `standalone` is `#[default]`. `github` scaffolds the rest: `.gitattributes` (CRLF normalize), a generic `VERSION` + stack-agnostic `.github/workflows/version.yml` patch-bump CI, and the tracked `claude-internal/` mirror (see below).

**`claude-internal/`** — a TRACKED folder at the project root, mirror of the gitignored env dir, so a blueprint's skills/memory/persona reach git. **Namespaced per blueprint** (`claude-internal/<name>/...`) so multiple blueprints sharing one repo don't clobber each other's mirror. Four parts: `claude-internal/<name>/skills/` ← `<env>/skills/`, `claude-internal/<name>/memory/` ← `<env>/projects/<encoded-cwd>/memory/`, `claude-internal/<name>/persona.CLAUDE.md` ← `<env>/CLAUDE.md` (renamed so Claude Code never auto-loads the snapshot), and `claude-internal/<name>/handoff.md` ← `<project>/<name>.HANDOFF.md`.

**Skills are one-way and pruned; memory is a union (`merge_dir`), and that asymmetry is the whole two-machine story.** A skill is regenerated from the role on every `place`, so a mirror-only skill is stale output — prune it. A mirror-only *memory note* is the opposite: it is the other machine's committed work, arriving by `git pull` into a folder `place` then mirrored over. The prune deleted it on the next launch and the next commit recorded the deletion, git history the only copy — **reproduced against the released binary: one `aello run`, one deleted note, staged**. So `mirror_env_internal` adds and never removes memory, and names the mirror-only notes on stdout pointing at `aello restore`. Real deletion is a `git rm` of the mirror copy — deliberate, not a side effect of launching. Do not "fix" the accumulation by restoring the prune.

**`handoff.md` is lowercase on purpose**: `*.HANDOFF.md` is gitignored in this repo (and the generated `/sync` is told never to stage the root file), so a snapshot named `<name>.HANDOFF.md` would be silently uncommittable — the exact shape of bug this repo keeps hitting. The root file stays the live one (written by `/handoff`, delivered and deleted by SessionStart); the snapshot is the only copy that crosses machines, which is why **`/handoff` must run before `/sync`** — both skill templates say so, and `docs/workflows.md`'s session loop was reordered to match. An absent root file never deletes the snapshot: absent means "not written this session", the same rule the persona snapshot follows.

The mirror is read back in exactly two places. `place` calls `restore_from_mirror` first, and when the mirror exists with no env dir beside it — a fresh clone — it seeds the env *from* the mirror (skills, memory, persona, and any waiting handoff). Without it the first `aello run` after a clone seeded a bare env and `copy_dir_all`'s prune then deleted everything the mirror held (measured here: 11 tracked memory notes and 6 skills against the 2 and 4 a placement seeds), silently, with no restore path anywhere in the codebase. Relatedly, `copy_dir_all` no longer prunes when its **source is missing** — the memory source encodes `current_dir()`'s exact spelling, so a case-variant launch dir points it at a directory that never existed and a wrong derivation is indistinguishable from a deletion. Seeded at placement (`scaffold_project` → `mirror_env_internal`, taking the blueprint name, github only, NOT added to the `.claude-env-*` gitignore) and refreshed + staged by the github `/sync` step, which self-heals the folder (`mkdir -p`) so already-placed envs adopt it.

**`project::restore` / `aello restore <name>`** is the second read-back, and the one the user invokes: the same adoption into an env dir that **already exists**, which `place` deliberately refuses (a live env must not be contradicted by a snapshot, and that refusal is what left the return trip broken — pull the other machine's notes and nothing read them). It is additive on purpose: memory and skills go through `merge_dir` so an unsynced local note survives, and a persona that differs from the snapshot is *reported* (`Restored::persona_differs`) rather than replaced, because `aello persona` is the one command that overwrites a persona. The single exception is the resume note, which is replaced — by then the local root note has already been snapshotted and committed by this machine's own `/sync`, so it is recoverable from git, while the mirror's copy is the one just pulled and the entire reason for running the command. Bails when no mirror exists (a `standalone` blueprint has none) rather than reporting a successful no-op, and bails on a Cline blueprint (no mirror is written for one). Cross-OS is free rather than handled: `memory_dir` derives `<encoded-cwd>` from the project path it is handed, in both directions, so no machine's path spelling is ever carried in the mirror — `a_restored_env_reads_memory_at_this_machines_path_spelling` pins it.

**Env dir** — `<project>/.claude-env-<name>/`, the blueprint's `CLAUDE_CONFIG_DIR`. Holds `settings.json`, the global persona `CLAUDE.md`, `.aello.toml` (the placed Instance), `hooks/post-compact.py` + `hooks/session-end.py` + `hooks/session-start.py`, and the generated `skills/sync/SKILL.md`. Gitignored by convention (the `github` cap seeds the `.claude-env-*` ignore line).

**Two CLAUDE.md layers** — global persona (`<env>/CLAUDE.md`, set once, never clobbered) vs project (`<project>/CLAUDE.md`, maintainer only, maintained by `/sync`). Memory is separate: `place` seeds a starter working-style memory under `<env>/projects/<encoded-cwd>/memory/` on first placement (gated on `MEMORY.md` absence, never clobbered), then it's automatic (PostCompact hook).

**Auth** — `aello login` runs `claude setup-token`, stores a long-lived non-rotating `CLAUDE_CODE_OAUTH_TOKEN` in `config.toml`; every env exports it. Concurrency-safe across many parallel envs (the reason credential-copy was abandoned). On fresh envs, `mark_onboarded` seeds `hasCompletedOnboarding` so Claude skips its first-run wizard.

**contextdb** — three transcript hooks. **PostCompact** saves each compaction summary; **SessionEnd** captures a session ended without compacting (`/clear`/exit), archiving the `/handoff` note + transcript pointer to `<ts>_<session>_end.jsonl` and skipping subagent sessions. **SessionStart** is the consumer side: it delivers `<name>.HANDOFF.md` and `<name>.NOTE.md` into the new session as `additionalContext` and **deletes** them, which is what makes the `/handoff` and `/note` skills' "read on boot, then deleted" true and stops SessionEnd re-archiving the same stale note forever. It also emits a **standing block on every session** — "you are running under aello, named `<name>`" plus the four facts a session cannot otherwise learn: the env dir is gitignored and rewritten every run (`.aello-keep` to pin a skill), the seeded skills are the user's to type, other blueprints may share the working tree, and commits are attributed automatically. **Why the hook and not the persona:** a session had no reliable way to know aello existed — the env dir is gitignored, the persona is user-owned and usually silent, and a project `CLAUDE.md` only exists for a maintainer — so agents edited files the next launch overwrote and ran skills that are the user's alone. The persona is also the file most likely to be rewritten wholesale, while `place()` rewrites this script every run, so the block reaches an env placed months ago without touching anything the user owns. ~257 tokens per session; `session_start_hook_announces_the_aello_environment` pins the parts that carry the meaning, including that it is emitted even when no handoff or note is waiting (the early `sys.exit(0)` used to skip it). Existing envs self-heal both into `settings.json` on next `place` (`ensure_own_hook(settings, event, script)`, idempotent, never clobbers a user-edited file; an unparseable one warns on stderr and is left alone). Transcripts → `<contextdb>/<project>/<blueprint>/<ts>_<session>.jsonl`. Root in `config.toml` (`contextdb`, default `~/aello/contextdb`), passed as `AELLO_CONTEXTDB`. **SessionEnd does all the archiving in practice** — audited 2026-08-03: 265 SessionEnd records and **zero** PostCompact records for any aello blueprint, the newest compaction capture seven weeks old and from a pre-aello setup. PostCompact fires only on compaction and a 1M-context session ended with `/clear` never reaches it; it is dormant, not broken (the same script produced correct 7 KB/15 KB captures in June), so it stays seeded. **Every env launches with `--thinking-display summarized`** (`launch.rs::THINKING_DISPLAY`, appended before the user's `--` extras so one run can override it). The API default is `omitted`: thinking blocks arrive with an empty `thinking` field and only an opaque signature, which is what the transcript stored — measured 2026-08-03, 2,842 blocks across 53 transcripts, every one empty. `display` controls visibility only (thinking happens and is billed identically), so this is free; the raw chain of thought is never returned on any model and a summary is the ceiling. The flag is real but **undocumented in `claude --help`** — found by grepping the binary, and verified end-to-end by running a prompt through it and reading the captured summary out of the archived transcript. Unconditional for the same reason the voice is: it applies to every env and no blueprint has a reason to differ. **SessionEnd copies the transcript** to `<ts>_<session>_transcript.jsonl` rather than only recording its path, and notes the result in `transcript_archived`. The path alone was a reference that decayed: Claude Code deletes its own session files after `cleanupPeriodDays` (**default 30**) and the env dir is gitignored + `--purge`-able, so 15% of archives already dangled with a clean cliff at 30 days (6–14% dead under, 44% at 30–39) — silently, since nothing errors. `CLEANUP_PERIOD_DAYS = 365` now goes into `settings_json`, and `ensure_cleanup_period` self-heals it into existing envs **only when absent** so a user's own value stands. The copy streams (transcripts reach tens of MB) and opens the source before the destination, so a failed copy leaves no 0-byte file masquerading as an archive. It also prefixes both paths with `\?\` on Windows: the encoded-cwd directory repeats the whole project path, so a deep project pushes the transcript past the 260-char MAX_PATH and `open()` fails — measured at 325 chars, where the archive silently degraded back to a pointer and the `except` recorded that honestly, which is exactly how it stayed invisible.

**voice** (unconditional — every env) — a `Stop` hook that speaks each response's trailing `TL;DR:` line via Edge neural TTS, plus a `SessionEnd` group that releases the leased voice. Vendored from the `revoiced` project as **five** files copied together into `<env>/hooks/` (`hooks_speak.py` → `speak.py`, `hooks_duck.py` → `duck.py`, `hooks_focus.py` → `focus.py`, `hooks_notify.py` → `notify.py`, `hooks_win_audio.ps1` → `win_audio.ps1`): `speak.py` does `sys.path.insert(HERE)` + imports `duck`, `focus` and `notify` as siblings, and shells out to `HERE/win_audio.ps1`. **Vendor all five.** `duck` and `win_audio` are hard dependencies — without them a copy fails at runtime. `focus` and `notify` are imported **guarded** (`try`/`ImportError` → `SimpleNamespace` stubs), and that guard is exactly the trap: a three-file vendor still speaks, while `notify`'s stub returns `False` from `show()` and **no desktop notification is ever attempted, in any env, silently**. That is what happened on 2026-08-02 — notifications were off across the machine for two hours, reported broken twice and measured healthy twice (the tests ran the repo's copy, which has its siblings, not the env copy the hook executes). Guarded means "survives a partial copy", not "optional". Upstream `e95bd2b` made the fallback loud: a `MISSING` list rides on every history entry and `speak.py --status` leads with `INCOMPLETE COPY - no …`. **Drift check:** upstream keeps a module-level `HOOK_VERSION` in `speak.py`, bumped only when one of the five hook-path files changes; `project.rs` records the vendored value in `HOOK_VERSION` (currently **19**), two unit tests fail if a re-vendor moves one without the other, and `aello voice status` prints it. **The bump covers CLI-only changes too** — settled with revoiced at 19, which moved only `--status`: the digest test here is byte-for-byte over all five files and cannot tell which half of a file changed, so an unbumped change fails it with no version to explain the mismatch. The version means "this exact set of bytes", not "the hook path moved". **13 added a Telegram sender** — the spoken line and its mp3 also go to a chat, opt-in behind `REVOICED_TELEGRAM=1` + `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` (all three, or it is off) — and touched `speak.py` only, which is exactly the case the second test exists for in reverse: the other four were byte-identical and still get re-vendored, because "only one file moved" is how a partial vendor gets rationalised. **14 fixed what 13 could not deliver**: Windows never pushes a newly-set User-scope variable into a running process, so at 13 the feature was live only in terminals opened afterwards and silently dead in every session already on screen — the switch reads as on while nothing is sent. 14 falls back to the persisted `HKCU\Environment` value when a name is *absent* from the process, never when it is present, so a blueprint's `REVOICED_TELEGRAM=0` still wins. Only `--status` distinguishes the two (it now names the source), and **only from a shell older than the variables** — a fresh shell inherits them and reports identically on both. **17 made an empty value off**: `tg_env` correctly returns `""` for a present-but-empty name, but `"" != "0"` is true, so a blueprint that set the variable to nothing opted *in* while the docstring one line up promised the opposite; `not in ("", "0")` is the fix. The obvious test agrees with the bug — PowerShell's `$env:X = ''` **deletes** the variable, so testing that way measures the *absent* case and reports a pass. **18 made a failed send visible.** A timeout, a revoked token, a wrong chat id and an API `ok:false` all produced exactly nothing: no history entry, no stderr, no retry, and the line still spoken locally. It lands in `state.json` as **`telegram_error`** — not on the history entry, because `record()` has already appended by the time the send is attempted (deliberately: a 30s upload must not sit between a finished turn and the station showing it), and rewriting the whole history on the hook path once per turn in 39 envs is not worth it. Cleared by the next success, so it reads "right now". **That is a new key revoiced owns and aello reads**: `voice.rs::status` prints it via `telegram_error_line`, and the round-trip test asserts a mute does not erase it — the two-writer rule, which is why the key is named here at all. The fix is upstream at 11 — **10 was an incomplete fix and damages the machine too**: it kept the record but keyed it on the *pid*, and one process owns several audio sessions (`GetAllSessions()` yields one control per session, so a browser's media and notification streams collide), so the second reading overwrote the first while both were lowered and the restore raised one and dropped the other's record. Measured here after the 41-env backfill at 10: five applications at 0.15 from a single duck. 11 keys on `InstanceIdentifier`, still reads the pid-keyed records that copies on 10 left behind, and stops `restore()` running unlocked on a merely contended lock. Envs adopt a bump on their next `run`, and until then their copy is the thing doing it — which is why **a re-vendor is a rollout, and the sweep afterwards has to be the registry scan, not a live audio-session enumeration** (see `docs/troubleshooting.md`: the live check found 1 damaged application where the registry held 7, because Windows stores per-app volume per *endpoint* and the live API reads only the active one). **15 turned that manual registry scan into the hook path** (`duck.sweep`, widened at 16), because 11 closed the compounding and not the two holes underneath it: the restore's liveness filter drops an application that goes quiet and then **exits**, leaving it lowered with no record at all — a reboot mid-turn is that for everything at once (upstream: duck at 11:15:39, machine down at 11:16:05, three applications back at 15%) — and one that returns carries a new pid, so its stored 0.15 is read as its normal and the next duck lands on 0.0225. `REVOICED_SWEEP` is `0` / `signature` / anything-else-is-the-default, and **the wide default is the right one**: `is_duck` reads `level` as it is *now*, so changing the duck in the station from 15% to 25% orphans every 0.15 already on disk, claimed by nothing and reported by nothing. An exact `0` is never touched — the clamp is 0.01, so a zero is somebody's own mute, and here that somebody is **Wispr Flow**, which zeroes everything while dictating and restores it. That makes revoiced the *second* ducker on this machine and the collision unfixable from either side: we lower 1.0 → 0.15, Wispr samples **0.15** as normal and zeroes, and whichever restores last wins — when it is Wispr the machine lands on 0.15. (Windows' own communications ducking is **not** the culprit: `HKCU\Software\Microsoft\Multimedia\Audio\UserDuckingPreference` is 3, "do nothing".) The sweep closes it one turn later, which is the other argument for the wide default — Wispr restores whatever it sampled, and any level but 0.15 is orphaned by the narrow rule. **Timing is load-bearing:** it runs at the *start* of a turn, before this turn's duck, because the registry lags the live session by seconds (a stored value still read 0.15 five seconds after `duck.json` was gone), so a sweep straight after our own restore finds its own duck and "repairs" it; it also refuses on a fresh speaker lock or an existing duck record, since a duck in progress is indistinguishable from one that failed. **Unverified, on the record:** repairs go through the live session where one exists (which writes through to every stored entry for that executable), and only where there is none does `_write_stored` patch the float at offset 8 of the `"3"` PROPVARIANT — that write provably persists (0.15 → 1.0 on ShareX, still 1.0 after), but whether the audio engine honours it at that application's next launch rather than overwriting from a cached copy is **not known**; if it does not, the registry half is decoration. A version, not a commit sha — revoiced's CI commits a `VERSION` bump on every push to main, so local shas get rewritten by the rebase and a recorded sha rots on its own. **Toast identity:** a Windows toast is shown *as* a registered AppUserModelID and one sent under an unregistered id is dropped with no error, so a machine that runs envs but never starts the revoiced station had notifications off everywhere — the same silent shape one layer out. `run_blueprint` calls `voice::ensure_notify_registered` after `place`, which runs the vendored `notify.py --register` unconditionally (best-effort; a missing `python` is not worth failing a launch over). Unconditional is safe **only since upstream `9d085c8`**, which split registration in two: the *identity* is a name any copy may claim, while the `revoiced:` *protocol* is a promise to run an `action.py` beside the copy that registered it — and an env's `hooks/` has none, since aello vendors the five hook-path files and not the station. Before the split, registering from an env repointed both toast buttons at a missing file, on exactly the machines a station had working; aello shipped a `reg query` guard for one release (v0.1.61) and dropped it once the default became correct. It lives in `run_blueprint`, not `place`, so the placement tests never spawn Python. **Don't gate it behind a marker file:** the handler command embeds absolute paths to `pythonw.exe` and `action.py`, so a Python upgrade or a repo move invalidates it — a marker is a cache that goes stale exactly when the truth changes, and re-registering every launch is what self-heals it. Registered as `$CLAUDE_CONFIG_DIR/hooks/speak.py` — **never a path to a checkout**, which is the whole point: that coupling silences every env at once when one directory moves. `sync_voice_hooks` self-heals registration into an already-placed env (register-only — there is no deregister branch, since no env is ever made silent by placement), replacing a hand-wired absolute-path group rather than adding beside it, and `ensure_tldr_instruction` appends the TL;DR section to the persona (append-only — the hook speaks that line and nothing else, so a persona that never writes one is silent). The scripts' state (voice pool, per-session leases, mutes) is **machine-wide**, not per-env: `%LOCALAPPDATA%\revoiced` / `~/Library/Application Support/revoiced` / `$XDG_DATA_HOME/revoiced`. That's what makes concurrent envs lease different voices and queue behind one playback lock. `voice.rs` (`aello voice mute|unmute|stop|status`) writes that shared state directly — no Python, no placed env, works from any directory — preserving unknown keys since the hook owns the rest of the file.

**Token accounting** (`tokens.rs`, `aello tokens`, TUI `T`) — read back out of the transcripts contextdb already archives, so it needed no new hook and works retroactively over history recorded before it existed. Sources are contextdb (`<root>/<project>/<blueprint>/`, every ended session anywhere) plus the *live* `<env>/projects/*/` dirs of blueprints placed in the cwd, so the session you are sitting in counts before it ends; sessions in other projects can't be reached at all, because contextdb records a project's folder *name*, not its path. Cline blueprints are skipped rather than reported as zero.

**Dedup by `message.id` is the feature, not a detail.** Claude Code writes one transcript record per **content block** and repeats the message's whole `usage` on each, so summing records roughly doubles the answer — measured here, 266 usage-bearing records for 173 distinct messages, overstating output by 68% (218,607 vs 129,877). That same dedup is also what makes reading two overlapping sources safe: 17 of 122 archives on this machine are a session archived twice, and every live file overlaps its own archive. `duplicate_message_ids_are_counted_once` pins it, and the CLI prints the collapse count — zero collapses on a real archive means the dedup broke, not that the run was clean.

Buckets are kept apart because they price up to 20x apart (cache read is 0.1x input, a 1h cache write 2x), and the 5m/1h split comes from `usage.cache_creation` when present, defaulting to 5m — the API default TTL — when it isn't. **That fallback is the one to watch**: re-measured 2026-08-10, *every* cache-write token on this machine (38.8M) is in the **1h** bucket and none in 5m, so a missed sub-object would silently understate the fleet by $145.63 rather than by a rounding error. The multipliers themselves were re-checked against the published pricing page the same day (5m 1.25x, 1h 2x, read 0.1x, all applied to the *input* rate and never to output). Worth stating because "cache is cheap" is only half true — reads are 0.1x input, but a 1h write costs *twice* plain input, and the token share misleads about the money: cache read is 98.4% of tokens but 70% of cost, cache write 1.2% of tokens but 18% of cost, output 0.4% of tokens but 13%. There is **no cache storage ceiling** to account for — nothing meters stored bytes; what exists is 4 breakpoints per request, a minimum cacheable prefix, and TTL expiry, and read tokens bill per request, which is why a re-read prefix accrues billions of read tokens without anything being stored repeatedly. **A model with no `RATES` entry is quarantined into `unpriced` and named on stdout, never priced at zero**: a cost that silently drops half the traffic is the exact shape of bug this repo keeps hitting. Rates match by *longest* prefix so `claude-opus-5` isn't swallowed by `claude-opus-4`, and Sonnet 5 is listed at $3/$15 rather than its $2/$10 introductory rate, because a price keyed to an expiry date goes quietly wrong the morning after and already-installed copies keep reporting the old number (offered again 2026-08-10 and declined again on the same grounds — the intro rate is worth **3 cents** across this machine's entire Sonnet 5 history of *two messages*, against a rate that would be wrong from 2026-09-01 in every installed copy). **The prefix match has one known wrong entry, left in deliberately:** `claude-opus-4` is $5/$25, right for Opus 4.5–4.8 but also swallowing `claude-opus-4-0` and `claude-opus-4-1`, which are $15/$75 — a 3x under-price. Not split because a model census the same day found zero such records (25,682 Opus 5, 16 Haiku 4.5, 4 Sonnet 5, nothing older) and the user's fleet only runs current models; it would bite only if an old archive were restored. Cost is **list API rates applied to subscription usage** — a what-if, never a bill — and both the CLI footer and the TUI pane say so.

**The 5-hour window's denominator is the honest part.** Blocks are global, not per env, because the quota is machine-wide (one shared token), with a per-env split inside the current block. But **the subscription's actual limit is in no transcript** — so the percentage is against *this machine's own peak block*, and the label names that ceiling rather than implying a plan quota aello cannot read. A block starts at the containing hour of its first message and closes after 5h or after a 5h gap, so an overnight pause is two blocks rather than one impossible one.

The scan is seconds, not milliseconds (322 MB / ~6 s here), which is fine per CLI invocation and fatal per TUI frame: the tab caches on `App::tokens`, and the `t` handler **paints a `SCANNING…` frame before running the scan** rather than after, since otherwise the terminal sits on the previous screen looking hung. `R` rescans. Verified end to end against real data 2026-08-10: the cost arithmetic reproduces independently to the cent, and the dedup reproduces a hand PowerShell measurement of the same transcript (173 messages, 129,877 output tokens). Re-verified later the same day from the `--json` output against the published rate card — $2,209.93 reported vs $2,210.31 hand-computed, the 38-cent gap being exactly the Haiku 4.5 / Sonnet 5 traffic priced at its own cheaper rates rather than Opus 5's.

**Git attribution** — with `github`, `launch.rs` sets `GIT_AUTHOR_*`/`GIT_COMMITTER_*` to `<blueprint> <blueprint@aello.local>`, and the `/sync` github section appends an `Env: <blueprint>` commit trailer. Multi-blueprint repos stay traceable via `git blame` / `git log --author`.

## Seeded skills are the user's to run, not the agent's

Every seeded skill is manual-only twice over. `disable-model-invocation: true` in the frontmatter blocks the Skill-tool path. `templates::manual_only` adds a banner under the H1 blocking the other one: an agent that opens the `SKILL.md` with `Read` and works through the steps has *run the skill*, whatever route it took. ## The four response rules ride on a per-turn hook, not the persona

`src/hooks_user_prompt_submit.py` is bundled and registered on every placement, injecting four rules on **every prompt**: be concise, don't be sycophantic, never hand over a plan, and close with one block — the `TL;DR:` line with 3–4 numbered next steps beneath it. ~300 tokens per turn.

**Steps and TL;DR are one rule, not two.** They shipped as separate rules and lasted about an hour: the summary said a thing, the steps repeated it, and the reader had to reconcile two closing sections. Merged, the spoken line introduces the list it sits on top of. The TL;DR grew to two-to-four sentences to absorb what the steps used to duplicate. **Ordering is constrained by `speak.py`, not taste:** `extract_tldr` matches `^…TL;DR:\s*(.+?)$` and takes the last match, so the line must stay on ONE line — a wrapped summary is spoken with its tail cut off, silently — while numbered steps beneath match nothing and are safe. Verified by running a sample through the real `extract_tldr`.

**The next-steps rule has two halves and only one of them survived the first draft.** Steps that *stand alone* are the point — the user skips the prose and acts on `1, 2, 3, 4` — and the first wording got correct steps sitting under an essay that still had to be read to make sense of them, which is exactly what it was written to prevent. So the rule now states the assumption outright ("assume the user skips every word above them", no step saying "as described above") **and** the concise rule caps the prose ("a few sentences — if something matters it goes in a step, not a paragraph"). They only work as a pair; loosen either and the wall of text comes back with a numbered list stapled to it.

**It also reads as the opposite of the no-plans rule if the wording is careless.** The line between them is whose hands the actions are in: a plan is what *the agent* is about to do, held for sign-off; the steps are what *the user* does next. The no-plans rule therefore no longer says "no numbered proposals" (it now says don't lay out what you intend to do and wait for sign-off), and the steps rule says "their actions, not yours" in as many words. The order on the page is fixed and stated in the rule: prose, then the `TL;DR:` line, then the steps beneath it, and nothing after those.

**All six bundled hooks decode their own stdin** — `json.loads(sys.stdin.buffer.read().decode("utf-8-sig", "replace"))`, the form `speak.py` has always used. `json.load(sys.stdin)` decodes with the console code page on Windows, corrupting every non-ASCII string in the payload. **What it does not do is raise**: measured at cp1252 / Python 3.14, `sys.stdin.errors` is `surrogateescape`, so a CJK character in a path returns as mojibake plus a lone surrogate and the blanket `except` in each hook never fires. The real cost is narrower than it first looked and lives in the paths: a `transcript_path` decoded that way does not open (measured, FileNotFoundError), so the SessionEnd archive degrades back to a pointer, and a mojibaked `cwd` misses the handoff/note lookup. The plan-mode denial and the per-turn rules were **never** at risk — `tool_name` is ASCII and the rules hook discards the payload — so those two are consistency, not a fix. The first version of this note said the plan block failed open; that was reasoned from the code, not measured, and it was wrong. CodeAuditor caught it.

**The no-plans rule is enforced twice**, like the seeded skills are. `src/hooks_pre_tool_use.py` is a bundled `PreToolUse` hook matching `EnterPlanMode|ExitPlanMode` (`PLAN_TOOLS`) that denies both, so plan mode is unavailable and not merely discouraged; the injected text is what catches the other route, a proposal written as ordinary prose, which is what a plan usually looks like. The **matcher** is load-bearing and is asserted by a test: an unmatched `PreToolUse` group fires on every tool call, which on Windows is a process spawn per `Read` in every env. `ensure_own_hook` gained `ensure_own_hook_matching` for exactly this. **What is measured and what is not:** a `PreToolUse` deny does block a tool and hand its `permissionDecisionReason` back (2026-08-03, against `Read` — it returned the reason instead of the file), and the matcher does scope it (a `Glob` in the same run never reached the hook). Whether the plan tools emit a `PreToolUse` event at all is **unverified** — `claude -p` never calls `ExitPlanMode` under `--permission-mode plan` across three attempts, so print mode cannot answer it and the check needs one interactive session. A denial appends to `<env>/hooks/plan-blocked.log`; nothing reads it, and it exists solely so the first real denial settles what the tests could not. An empty log everywhere means the block never fires and the text is carrying the rule alone — which is the guard-that-never-fired shape this repo keeps hitting, so check it rather than assuming.

**Why per turn.** All four govern how a single response is written, and style decays — an instruction delivered once at session start is buried by turn eighty, which is when padding and reflexive agreement return. **Why not the persona.** It is written once and never clobbered, so an edit there reaches *no* existing env; `place()` rewrites this script every run, so a wording change reaches all of them on their next launch. It is also the file most likely to be rewritten wholesale — `/regenerate-claude-md` exists to do exactly that — which is a poor home for the voice's only input.

Started as a hand-registered experiment in TechnicalDirector on 2026-08-03; bundled on the same day once the user asked for conciseness and anti-sycophancy fleet-wide, since this was already the only channel that self-propagates. `ensure_own_hook(settings, "UserPromptSubmit", "user-prompt-submit.py")` heals it into existing envs, and it runs **before** `ensure_tldr_instruction` so an adopting env stops getting the persona append on the same placement rather than one run later.

`ensure_tldr_instruction` + `injects_tldr_per_turn` survive as a **fallback**: unregister the hook by hand and the persona append returns, so the voice can't go silent for want of an instruction. The 40 envs placed before this carry the TL;DR section in their personas already and will now also get it per turn — duplicated, harmless, and not worth editing a user-owned file to fix. Enforcement never really lived in either place: `speak.py` exits 2 on a response with no TL;DR line and asks for one, so the instruction only ever saved a round trip.

`user_prompt_submit_hook_carries_the_five_response_rules` pins the wording, because the injected text *is* the product here — a dropped rule would be invisible.

## Seeded skills are regenerated — `.aello-keep` opts out

All four seeded skills are written **unconditionally on every `place`** (no existence check), which is what makes a role change reach an env placed months ago. The cost: a skill hand-edited for one project was silently restored to the generated version on the next run, and — worse — the github `/sync` step then mirrored that generated version over the custom one in `claude-internal/`, committing it. The edit survived only in git history, nowhere anyone would look.

`<env>/skills/<skill>/.aello-keep` (empty file) pins one skill: `place` neither regenerates nor removes it. The removal branch matters — a hand-written `/sync` isn't stale just because the blueprint became standalone, so a kept skill skips `remove_file` too. `skill_kept` + `seed_skill` in `project.rs`; the marker lives beside the skill rather than in `config.toml` so it travels with the env dir and is visible where the editing happens. A kept skill no longer tracks its role — that's the trade, and deleting the marker restores the generated version.

## `/sync`

Generated per blueprint from its role's capability expansion (`templates::render_sync_skill`), seeded to `<env>/skills/sync/SKILL.md` when `caps.any()` — i.e. everything but `standalone`. Manual-only (`disable-model-invocation: true`) — replaces the old auto-commit hooks. A `standalone` blueprint gets no skill at all; a `contributor` gets git + `CHANGELOG.md` and no README/docs/project-CLAUDE.md sections. Sections, in order: repo health (github), reconcile **memory first** then the enabled docs (two-way), mirror env config into `claude-internal/<name>/` + stage by path (github), commit + rebase-before-push with `Env:` trailer (github).

The staging rule ("only what you created or modified this session") has one carve-out that has to stay explicit: `*.HANDOFF.md` and `*.NOTE.md` are created *during* the session and deleted on the next boot, so the rule as literally written told you to commit them. In a repo aello scaffolds they are **not** gitignored — the `github` role seeds only the `.claude-env-*` line — so nothing else stops it, which is why the carve-out has to be in the skill text rather than left to `.gitignore`. (aello's *own* repo does ignore `*.HANDOFF.md` and `*.NOTE.md`, added by hand in `dec3fd9`. That is belt-and-braces here and says nothing about the repos the skill is generated into — don't drop the carve-out on the strength of it.)

## `/handoff`

Universal counterpart to `/sync` (`templates::render_handoff_skill`), seeded **unconditionally** for every blueprint at `<env>/skills/handoff/SKILL.md` (no role gate — even a standalone blueprint gets it). Manual-only (`disable-model-invocation: true`), tools `Write, Read, Bash`. At session end it writes a transient, untracked `<name>.HANDOFF.md` at the project root so the next session resumes after a full `/clear` (not a compact — a clear leaves no summary, so the note is fully self-contained: read-first pointers, what shipped + commit shas, open threads/next steps, gotchas). The filename is **prefixed with the blueprint name** so co-located blueprints in one repo don't clobber each other's handoff; the SessionEnd hook reads the same `<name>.HANDOFF.md` (it derives the name from `CLAUDE_CONFIG_DIR`). Read on boot, then deleted.

**The root file is untracked; a copy of it is not.** `/sync`'s mirror step snapshots it to `claude-internal/<name>/handoff.md` (see above), which is committed and is the only way a resume note reaches a second machine — the skill used to say "`<name>.HANDOFF.md` is **never committed**" full stop, which became false as written the moment the snapshot existed, and two seeded skills contradicting each other is worse than either being wrong. Both now scope the claim to the root file and both state the ordering (`/handoff` first, then `/sync`), pinned by `the_handoff_skill_scopes_never_committed_to_the_root_file` and `sync_carries_the_handoff_across_machines_without_committing_the_root_file`.

## `/note`

Universal too (`templates::render_note_skill`), seeded **unconditionally** for every blueprint at `<env>/skills/note/SKILL.md` alongside `/handoff`. Manual-only (`disable-model-invocation: true`), tools `Write, Read, Bash`. **The target need not share this repo** — the skill resolves the target's project root and writes there, because the SessionStart hook only reads its *own* project root, so a cross-repo note left here is a dead letter that looks delivered. It originally assumed one shared repo and reported a target it couldn't find here as a typo; that misdiagnosed the common multi-repo case twice on 2026-08-02. Casing must be the blueprint's canonical form (the hook matches `<Name>.NOTE.md` exactly — wrong case is silent on a case-sensitive filesystem). Distinct from `/handoff`: `/handoff` is a note to *self* for the next session, `/note <target>` leaves a note **for another environment** — the common multi-blueprint case where one env touches something the other owns, or hits a problem on its side. Invoked with the target blueprint name as the argument (`/note frontend`); the note **overwrites** `<target>.NOTE.md` at the project root (the target env's inbox) with a single current note — the target reads it immediately and deletes it, so only the latest matters. Heading `from <name>` attributes the authoring blueprint; sections: what I was doing / the problem / what you need to fix.

## `/twosentences`

Also universal (`templates::render_twosentences_skill`), seeded **unconditionally** for every blueprint at `<env>/skills/twosentences/SKILL.md` alongside `/handoff`. Manual-only (`disable-model-invocation: true`), no tools (empty `allowed-tools` — it's a pure text task). Condenses the previous assistant response into exactly two sentences, output with no other text.

## Development rules

- **Every user-facing change gets a `CHANGELOG.md` entry**, in the same commit as the code.
- **Small, scoped commits** — one change per commit; don't bundle unrelated edits.
- **Verify**: `cargo build --release` + `cargo test` must be green before pushing. Add a test for new behavior (templates/place/launch logic is all unit-testable without launching Claude).
- **Simplicity & surgical edits** — minimum code; match surrounding style; touch only what's required.

## Release process

Push to `main` → GitHub Actions:
0. **test** job runs `cargo test` on `ubuntu-latest` **and** `windows-latest`, and `bump` `needs` it — so a red suite blocks the release *and* the version bump. Gating the bump is the point: a bump commit pushed for a build that then fails strands a version that was never released and the next push bumps past it. Added 2026-08-08, because **no workflow had ever run the tests** — the suite only ever ran where a human ran it, which is Windows, so nothing had executed it on Linux even though CI builds a Linux target every push and `docs/development.md` already claimed the hook-digest test was CRLF-normalised "so a Windows checkout and Linux CI agree". macOS is deliberately uncovered (source-only). **Never add `--locked`**: the bump job commits a new `Cargo.toml` version without touching `Cargo.lock`, so the lockfile's package version trails by one from the next push onward and `--locked` would fail every run on a meaningless mismatch.
1. **bump** job resolves the version to release: if `Cargo.toml`'s version **already has a `vX.Y.Z` tag** it increments the patch (+0.0.1), commits `release: vX.Y.Z [skip ci]` and pushes via `GITHUB_TOKEN` (does not re-trigger CI); if it does **not**, a human set it by hand and it ships **exactly as written**, with no bump commit. That second branch is why `v0.2.0` exists — a patch bump can only ever produce X.Y.(Z+1), so a deliberate minor bump used to come out as 0.2.1 and the intended version never existed. Needs `fetch-depth: 0` + `fetch-tags: true` at checkout, or every version looks unreleased and the same one is republished forever.
2. **build** jobs (ref: the bump commit sha, so the binary reports the new version) build four targets: `x86_64-unknown-linux-gnu` → `aello-x86_64-linux`, `x86_64-pc-windows-msvc` → `aello-x86_64-windows.exe`, `aarch64-apple-darwin` → `aello-aarch64-macos`, `x86_64-apple-darwin` → `aello-x86_64-macos` (the Intel Mac build cross-compiles on the Apple Silicon runner). All are **unsigned** — no Apple Developer account, no Windows cert; `install.sh` clears the macOS quarantine xattr and the README documents SmartScreen. The asset↔platform map is duplicated in `update.rs` and `install.sh`; change all three together.
3. **publish** generates `SHA256SUMS` (`sha256sum aello-*`) and uploads the binaries + `SHA256SUMS` to **two** releases: the immutable **`vX.Y.Z`** tag (created at the bump commit, flagged `--latest`) and the permanent rolling **`latest`** tag (`--clobber`, explicitly `--latest=false`). `aello update` hits `/releases/latest` → resolves to the versioned release; `install.sh` and old binaries hard-code the `latest` tag's download URL, which is why both are published. `aello update` verifies the downloaded binary against `SHA256SUMS` before installing (verify-if-present, so releases predating the manifest still update), so keep publishing it. Never delete+recreate a release (a draft state breaks `aello update` with a 404).

Release notes must **end with the build sha** — `aello update` reads the commit from the last whitespace token of the body. After CI, `git pull --rebase` to sync the bumped `Cargo.toml` before the next local `cargo install`. Minor/major versions are bumped manually in `Cargo.toml`. If a plain push doesn't trigger the workflow, `gh workflow run release.yml --ref main` is the fallback.

## Build & install

```sh
cargo build --release          # writes to target/ — safe while aello is running
cargo test                     # unit tests, no Claude launch needed
cargo install --path . --force # replace ~/.cargo/bin/aello with the local build
```
